---
title: "v0.4.0-preview.3"
---

Released on 2026-11-20 (`v0.4.0-preview.2..v0.4.0-preview.3`, changes since `v0.4.0-preview.2`).

`v0.4.0-preview.3` lets agents report `idle` and, behind `lifecycle.idle_suspend`, has the Hub suspend idle agents and wake them when new work arrives. Multiple-choice decisions move to a single `web.decisions` experiment with Decisions wire names and CLI flags, project and profile Decisions pages, and withdraw and dismiss actions. Flat Cloud Run Runtime Brokers get native per-agent GCP identity and require `block_service_account`, global skill and template writes need their own `*_global` permissions, and the `core` skill scope is retired. Experimental exec schedules, message policies, webhook and GitHub triggers, ephemeral Cloud Run agents and Workload Identity binding at service account mint also land. The downgrade floor rises to `nightly-20261121`.

---

## Highlights

### 1. Agents Report `idle`, and Idle Agents Can Suspend Themselves

Agents end each turn with `blocked`, `idle`, `task_completed` or `ask_user`; `sciontool status idle "<reason>"` marks an agent as having nothing to do until new work arrives, and like `blocked` it is never marked stalled. A harness that cannot reach its model shows a `harness_error` activity instead of STALLED. Behind the `lifecycle.idle_suspend` experiment (alpha, off by default) with `server.hub.auto_suspend_idle` on, the Hub suspends agents that stay idle, completed or in a harness error for `server.hub.idle_suspend_after` (default `15m`), and any message, mention, notification or scheduled message wakes them. See [Ending a turn](/scion/concepts/#ending-a-turn-blocked-idle-task_completed) and [Auto-Suspend of Idle Agents](/scion/local/agent-lifecycle/#auto-suspend-of-idle-agents).

### 2. Decisions: One Experiment, Project and Profile Pages, Withdraw and Dismiss

Choices are now Decisions: `web.decisions` replaces `web.chat_choices` and `web.project_decisions`, agents send prompts with `scion message --decisions`, and each project and profile gets a Decisions page listing what is waiting on you and the log of decisions made. Agents read and record answers with `scion decisions list`, `show` and `record`, and retire decisions they no longer need with `scion decisions withdraw`; users can dismiss stale ones. See [Multiple-Choice Decisions](/scion/hosted/user/messaging/#decisions-experimental).

### 3. GCP Identity on Flat Cloud Run, Global Catalog Permissions and Exec Schedules

Flat Cloud Run instances run per-agent GCP identity natively, with an `assign` allow-list, explicit `passthrough` and, behind `hub.flat_runtime_brokers`, a default service account per Runtime Broker. Writes on global skills and templates are decided only by the new `*_global` permissions. Behind `hub.exec_schedules`, `scion schedule create --type exec` and `create-recurring --type exec` run a command in an agent's container with no message and no model turn. See [Flat instance runtime target](/scion/reference/server-config/#flat-instance-runtime-target-serverbrokerinstancesruntime_target) and [Exec Schedules](/scion/hosted/user/scheduling/#exec-schedules-experimental).

## ⚠️ Breaking Changes
- **Downgrade floor raised to `nightly-20261121` (#4962, #5067, #5084):** The decision log gains `withdrawn` and `dismissed` states, a `dismiss` answer outcome and new fields that older releases cannot read, so `DowngradeFloor` rises from `nightly-20261112`. Self-update refuses `v0.4.0-preview.2` and earlier as downgrade targets (`below_downgrade_floor`). Because that nightly is dated after `v0.4.0-preview.3` was published, self-update from `v0.4.0-preview.3` refuses targets older than 2026-11-21 (`#5205` later corrected `DowngradeFloor` to `nightly-20261120` so subsequent releases accept `v0.4.0-preview.3` as a downgrade target). See [Upgrading and Rolling Back a Hub](/scion/reference/hub-upgrade-rollback/).
- **Decisions use a single `web.decisions` experiment (#4962):** `web.chat_choices` and `web.project_decisions` are retired. A Hub that had them on must turn on `web.decisions` to keep decisions. While it is off, sending a decision prompt is refused with `400 experiment_disabled` and decision routes answer `404`; stored decisions and answers are kept.
- **Choices renamed to Decisions on the wire and in the CLI (#4967, #4972, #4987):** Prompt and response messages are `decision-prompt` and `decision-response`, and a set of answers is posted to `POST /api/v1/decision-prompts/{messageId}/answers`. Prompts sent before the upgrade (`choice-prompt`) no longer show as cards in chat history, and a set answer to one returns `404`; each decision in them can still be answered on its own. `scion message --decisions` and `--decisions-file` replace `--choices` and `--choices-file`, which stay as hidden, deprecated aliases.
- **Global catalog writes need the `*_global` permissions (#4796, #4804, #4856):** Updating or deleting a global skill needs `skill.update_global` or `skill.delete_global`, and creating, updating or deleting a global template needs `template.create_global`, `template.update_global` or `template.delete_global`. Plain `skill.update`, `skill.delete` and `template.*` no longer write global records, and owning one grants nothing. The `global-catalog-author` role (revision 3), `hub-admin` and `super-admin` carry the new permissions; mint new hub tokens with the matching `*_global` scopes for CI. See [Hub-boundary tokens for global catalog authoring](/scion/hosted/user/personal-access-tokens/#hub-boundary-tokens-for-global-catalog-authoring).
- **The `core` skill scope is retired (#4852):** Skills have `global`, `project` and `user` scopes. A one-time startup migration moves each `core` skill to `global` (a slug that collides is renamed `<slug>-core` and logged) and rewrites stored `skill://core/<slug>` references to `skill://scion/global/<slug>`. `--scope core` is refused.
- **Flat Cloud Run instances require `runtime_target.block_service_account` (#4940, #4944):** A flat `cloudrun` entry in `server.broker.instances` without `block_service_account` (a no-role service account distinct from `service_account`) fails validation and is not activated. Agents with no GCP identity, `block` or a confined default `passthrough` run as that account, and existing no-identity agents recreate their Cloud Run instance as it on their next start. Agents whose harness needs Google Cloud credentials are refused at Hub preflight unless given `assign` or explicit `passthrough`.
- **Helm releases named `*-scion-hub` are renamed on upgrade (#4917):** The `scion-hub` chart no longer collapses a release name ending in `-scion-hub` onto a sibling release's object names, so `helm upgrade` recreates its namespaced and cluster-scoped objects under `<release>-scion-hub`. `scion-hub` and `scion-hub-*` names are unchanged. Set `fullnameOverride: <release>` before upgrading to keep the old names. See [Upgrade impact](/scion/hosted/ha/helm/#upgrade-impact).
- **Antigravity and Codex model aliases:** The antigravity harness-config maps `large` and `extra-large` to `gemini-4-neon-medium` and `gemini-4-neon-high`, and its image installs `agy` with the upstream installer at build time instead of a pinned version (#4820). The codex harness-config maps `large` and `extra-large` to `gpt-6.2-sol` and `gpt-6.2-astra`.

## 🔐 Security & Access Control
- **Agents without credentials get none on start and restart (#4901):** An agent created without credentials (role `none`, the `none` auth choice, or the fallback when none was found) no longer receives secrets or harness credential settings at start or restart, as was already the case at create. The only exception is the git token, `GITHUB_TOKEN`, from the project and then the owner.
- **Project secret metadata needs `project:secret:read` (#4947, #4958):** An agent must hold `project:secret:read` to read project secret metadata, and project environment reads leave environment-secret metadata out for agents without it.
- **Identity-token minting checks delegation standing (#4898):** Minting an OIDC identity token is refused for an agent whose delegating user is suspended or removed from the project, even while the agent holds an unexpired Hub token.
- **Agent credentials revoked atomically on hard delete (#5002):** A hard-deleted agent's remaining credentials are revoked in the same transaction that deletes it, and a failed create's compensation writes an `agent_create_dispatch_failed` audit record.
- **Invited-user guardrails (#4891, #4902):** An invited user who has not signed in yet gets their Hub role at first sign-in; until then they cannot be promoted, added to a group carrying a built-in Hub role, or have their status changed. The admin users page and project members editor show these limits.
- **Smaller hardening (#4886, #4910, #4889, #4973):** `sciontool` strips credential and `X-Scion-*` headers when a Hub request is redirected to another origin. `capture_auth.py` is staged only when the harness-config policy allows it. Reading a project checks access before creating missing project groups. `GET /api/v1/projects/{id}/github-permissions` reports the same defaults token minting uses.

## 🤖 Agent Lifecycle & Workspaces
- **`idle` activity and honest stall detection (#4884, #4888, #4874, #4919, #5059):** `sciontool status idle` sets the always-on `idle` activity. A harness that cannot reach its model shows `harness_error` with the error; long tool calls and background jobs no longer trip a false STALLED because the Hub also checks the container for live work; and an agent that stalls without ever reporting a hook event gets a status message pointing at a startup problem. Completed, idle and harness-error activities are kept across a suspend.
- **Suspend reasons and suspended agents that stay suspended (#4904, #4981):** `scion list` and the API show why an agent was suspended (`user`, `idle` or `stalled`). Once an agent is suspended, late status and runtime reports no longer change its phase, activity or suspend reason.
- **Shallow-clone orientation (#4833, #4838, #4853):** Per-agent clone containers get `SCION_GIT_DEPTH` (`1` by default, `0` for full) and are told at startup how to deepen; `clone_depth` on a template or profile asks for more history. A worktree-per-agent agent that falls back to an in-container clone is labeled `clone-per-agent`. See [Shallow Clones & Full Clones](/scion/local/workspace/#shallow-clones--full-clones).
- **Parallel checkout everywhere (#4850):** Shared clones and `git worktree add` use the same parallel checkout workers as `sciontool init` (default 16, `SCION_GIT_CHECKOUT_WORKERS`).
- **Reincarnate and harness switch fixes (#4793, #4845, #4900, #4836):** The Agent home reset behind `reincarnate --harness` works on Kubernetes. A harness switch and every start of a reincarnated agent carry the environment gathered for `as_needed` entries, and a switch that fails after the reset names a recovery command the agent accepts.
- **One runtime at a time (#4858, #4866):** On start and on an unscoped stop, a Runtime Broker stops an agent's container left in a previous runtime (or refuses the start). On Cloud Run Instances an agent that reports `limits_exceeded` has its run stopped instead of being restarted.
- **Start and create guards (#5073, #5068, #5069, #4830):** Creating an agent with a profile the Runtime Broker cannot resolve fails up front with `runtime_unavailable` and lists the valid profiles. A start refused with `503 runtime_unavailable` reverts the run ID and any reincarnate config change. An empty built-in generic harness command is refused. Cloud Run refuses worktree-per-agent workspaces with `412` before anything is created.
- **Harness fixes (#4832, #4862, #4863):** Codex agents no longer report completed at every turn end. `readonly` agents can report their own status. Auto-suspend decides resume support from the harness type, so custom-named harness-configs are no longer skipped.
- **ffmpeg in agent images (#4937):** Agent images include system `ffmpeg`, and `sciontool init` registers it in Playwright's browser registry in the Agent home.

## 💬 Chat & Messaging
- **Reply all (#4816):** A chat message's Reply all action starts a reply with `@`-mentions for the other participants, leaving out you and the sender.
- **Wake for chat scheduled sends and clearer schedule detail (#4827, #4815, #4819, #4837):** Chat scheduled sends can opt in to waking a suspended agent. CLI and web schedule detail show the wake and interrupt settings, a scheduled message to a suspended agent says so and suggests `--wake`, and schedule views say they show only the caller's schedules.
- **Scheduled agents pick a Runtime Broker like a manual create (#4847):** A `dispatch_agent` fire selects its Runtime Broker the way a create without `--broker` does, and fails where a manual create would ask for `--broker`.
- **Mention fixes (#4834, #4905, #4933, #4980, #4821):** `scion message --in/--at @agent` resolves the agent and rejects invalid targets. `@agent's` (straight or curly apostrophe) resolves to the agent. An `@<email>` is highlighted only for a known Scion user, held web messages keep their `@email` mentions when delivered later, and unread mention dots are recorded for wrapped mentions and broker sends.
- **Discord attachment-only messages (#5054):** Discord tells an unresolved sender why an attachment-only message was not delivered.

## ☁️ Runtime Brokers, Settings & Operations
- **GCP identity on flat Cloud Run instances (#4940, #4944, #4941, #4946, #4974, #4982):** Flat Cloud Run instances always run per-agent GCP identity natively. `runtime_target.assignable_service_accounts` lists the accounts `assign` may attach (others are refused with `400`), explicit `passthrough` runs as `runtime_target.service_account`, and an identity change recreates the agent's Cloud Run instance on its next start. Behind `hub.flat_runtime_brokers`, `scion project identity default set|unset --broker` and **Project Settings** set a default service account per Runtime Broker. `scion doctor` checks `iam.serviceAccounts.actAs` on every configured agent account. See [Per-Broker Default Service Accounts](/scion/hosted/ha/permissions/#per-broker-default-service-accounts).
- **Flat Runtime Broker placement and conversion (#4800, #4801, #4824, #4798, #4806, #4794, #4948):** The web create page can place an agent on a flat instance, `scion hub brokers` shows each Runtime Broker's target, and Admin > Server Config edits `server.broker.instances`. `scion runtime-broker convert` turns legacy Cloud Run profiles into flat instances (folding `cloudrun.block_service_account` and `assignable_service_accounts` onto `runtime_target`), applies and rolls back several instances at once, and a co-located server refuses an instance another live server holds (`instance_in_use`).
- **Project shared directories on Cloud Run Instances (#4823, #4822):** The `cloudrun` runtime mounts a project's shared-directory NFS leaves into agents. The read-only `~/.scion/secrets` mount is removed, and a file-secret target that cannot be written is reported.
- **Separate internal Hub URL for broker plugins (#4861):** `server.hub.internal_url` sets the Hub URL that hub-managed broker plugins (Slack, Discord, Telegram, Teams) call the API on; plugins also receive `public_url` for browser links.
- **Separate Conduit relays on GKE (#5085):** The Helm chart's `conduit.relayMode: external` runs Conduit session hosting in its own relay pods with PodDisruptionBudgets. See [Separate Conduit Relays and PodDisruptionBudgets](/scion/hosted/ha/helm/#separate-conduit-relays-and-poddisruptionbudgets).
- **Plugin updates into an unwritable directory (#4912, #4930):** An admin plugin update whose binary lives in a directory the Hub cannot write installs the rebuilt binary under `<pluginsDir>/broker/`, or fails with `422` and guidance while the running plugin keeps running; the web shows the relocation and warnings.
- **Managed-agent creation is a request flag (#4818):** The Hub reads managed-agent creation from `managedAgent` on the create request; the legacy `managed-agents` profile value is still accepted and converted.
- **Image tags and hub-gke (#4999, #5000):** Nightly builds join release builds in tagging bundled `scion-*` images with their own version, the hub-gke image is stamped with its version, and the hub-gke Terraform turns off the chart's GKE secret mode.
- **Smaller fixes (#4859, #4966, #5040, #5053, #4922, #4911, #5052, #5051, #5033, #5036):** The Hub logs each agent's entry into the error phase with its stage. `scion list --format json` reports each agent's harness type and capabilities. `scion hub brokers info` and `delete` show a Runtime Broker's projects. `scion notifications subscriptions` respects `--project`. System image builds take their harness list from the bundled harnesses. The Hub refuses a file-backed SQLite database that did not enter WAL mode, unencodable Cloud Logging attributes are replaced, and a Secret Manager response without a payload is an error.
- **Versioned documentation site (#4921, #4936, #4978):** The site publishes snapshots for release tags at `/scion/<tag>/` alongside channel aliases, with a channel and version selector in the header.

## 🧪 Experiments & Groundwork
- **Idle auto-suspend and auto-wake (#4904, #5012, #5071, #5100):** Behind `lifecycle.idle_suspend` with `server.hub.auto_suspend_idle` on, the Hub suspends agents that have been `idle`, `completed` or `harness_error` for longer than `server.hub.idle_suspend_after` (default `15m`, minimum `5m`), records suspend reason `idle`, and wakes an agent the Hub suspended when a message, mention, notification or scheduled message arrives. Blocked agents and agents a user suspended are never touched. An idle suspend is durable: the final write is retried and the sweep completes interrupted suspends. Both settings are in **Admin > Server Config**.
- **Decisions (#4802, #4799, #4807, #4829, #4849, #4908, #4896, #4918, #4879, #4893, #4894, #5067, #5084, #5082, #4851):** Behind `web.decisions`, `scion decisions list`, `show` and `record` let an agent list, read and record interpreted answers, and `scion decisions withdraw <key>... [--set] [--reason <text>]` retires its own unanswered decisions. In human mode `scion decisions list` shows what is waiting on you, with `--made`, `--all-projects`, `-q`, `--conversation` and `--agent`. Project and profile Decisions pages, a header badge and one coalesced bell notification show open prompts, decisions stay answerable after chat retention purges the prompt, and users can dismiss stale decisions with a reason. Recommended choices are outlined, not preselected, unless the profile setting asks for it.
- **Exec schedules (#4906, #4895, #4938, #4957, #4961, #4964, #5089):** Behind `hub.exec_schedules` (with `hub.conduit`), one-shot and recurring exec schedules run a command in an agent's container over its Conduit session from the CLI, API or web schedule forms, with run history. The creator needs attach permission on the target agent; output is not stored.
- **Message policies (#5078):** Behind `hub.message_policies`, project admins write CEL policies on outbound agent messages to users, conversations and decision prompts in shadow or enforce mode, managed with `scion message-policy` and `/api/v1/projects/{id}/message-policies`.
- **Webhook and GitHub triggers (#5004, #5079, #5080, #4970, #4984, #5010, #5095, #5097):** Behind `hub.triggers`, projects define webhook endpoints and triggers that deliver messages to agents when signed webhooks arrive. With `hub.github_triggers` too, the Hub accepts GitHub App webhooks (dropping replays and its own App's events), reports App readiness, routes to a project's primary repository and offers trigger presets; trigger rules can be written in CEL from the CLI.
- **Message delivery over the Conduit session (#4875, #4935):** Behind `hub.conduit_deliver`, Cloud Run agents receive messages over their Conduit session instead of runtime exec, and a message that arrives before the session is up is retried.
- **Workload Identity binding at service account mint (#4975, #4985, #4992):** Behind `hub.k8s_workload_identity_setup`, minting a project- or Hub-scoped GCP service account also grants `roles/iam.workloadIdentityUser` for each Kubernetes runtime target that sets `workload_identity_pool`; the web mint dialog lists the bindings and the service account status view reads them from IAM.
- **Ephemeral agents on Cloud Run (#4877):** Behind `hub.cloudrun_ephemeral_agents`, an agent can be created with `persistence: ephemeral`; its home and workspace live in instance memory and start fresh at every start.
- **Runtime orphan report (#4868):** Behind `hub.runtime_orphan_reconcile`, the Hub reports runtime objects no Hub agent owns in logs, the `scion.hub.runtime_orphans` gauge and `GET /api/v1/admin/runtime-orphans`. Nothing is stopped or deleted.
- **System One administration (#4934):** Behind `hub.system_one`, Hub admins manage System One provider instances with `scion admin system-one instance create|list|delete|probe`.
- **Experiment-gated platform skills (#4846, #4864):** A platform skill, or part of one, can declare `experiment: <id>` and is included only while that experiment is on; the new `scion-artifacts` skill is gated on `hub.artifacts`.

## 🎨 Web UI
- **Header mode switcher (#4983, #5007):** The switcher reads Console, Chat and Terminals, and Terminals shows how many terminal sessions are open.
- **Idle and suspend display (#5071):** Agents show the `idle` and `harness error` activities and why a suspended agent was suspended, for example **suspended · completed (idle)**.
- **Smaller fixes (#4971, #4916, #4920):** The agent page's Messages tab scrolls with the composer in view, decision set headers stay horizontal, and the terminal's Capture Auth action says when the script is unavailable.
