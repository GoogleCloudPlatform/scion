title: "v0.4.0-preview.1"
---

Released on 2026-11-11 (`v0.3.0-preview.7..v0.4.0-preview.1`, changes since `v0.3.0-preview.7`; `v0.3.0` was tagged on the same commit as `v0.3.0-preview.7`, so this range also covers every change since `v0.3.0`).

`v0.4.0-preview.1` opens the `v0.4.0` preview cycle. User-scoped secrets that an agent saves now wait for the owner's approval, Hub-scoped secrets reach agents only in `always` mode or through the harness credential pass, and the Secret Manager migration verifies every value it writes. Artifact grants become a ladder (read, review, write, admin) with a stored-grant migration that raises the downgrade floor to `nightly-20261112`, the Hub can serve shared artifacts from a separate content host, and chat writes are decided by chat permissions with a new built-in `project-viewer` role. Release builds default their bundled agent images to their own version tag, Hub-side git refuses SSH repository URLs, `sciontool init` drops `CAP_NET_ADMIN` after network setup, and orphaned agents are visible across the CLI, web and API. Experiments add multiple-choice decisions, leaving a project, a welcome project in the setup wizard, and applying and rolling back legacy Runtime Broker conversions.

---

## Highlights

### 1. Owner-Approved Agent Secrets, Narrower Hub Secret Delivery and a Verified Secret Manager Migration

A user-scoped secret saved by an agent, for example a credential captured after you sign in inside an agent, is held as pending and is delivered to no agent until you approve it with `scion hub secret pending` or from Profile → Secrets in the web UI. Hub-scoped environment secrets are delivered at start and restart only in `always` mode; `as_needed` secrets are filled only by the harness credential pass for keys the harness asks for. The migration to GCP Secret Manager now runs as a Hub maintenance migration that decodes, writes and reads back each value, and `scion hub secret migrate` refuses to run. See [Approving user secrets saved by your agents](/scion/hosted/user/secrets/#approving-user-secrets-saved-by-your-agents).

### 2. Artifact Grant Ladder, Separate Content Host and Chat Permissions

Artifact grant levels are now read, review, write and admin, each including the levels before it, and the separate review-only grant path is removed. An opt-in `server.hub.content_url` serves artifact share links and HTML artifact views from a second public origin that strips credentials and answers `404` for every other route. Chat send, history, thread actions, uploads and topic creation are decided by chat permissions, and the built-in `project-viewer` role reads a project and its chat without posting or creating agents. Hub user JWTs and Conduit sessions carry the user's session generation, so revoking a user's sessions also ends them.

### 3. Release-Matched Agent Images, HTTPS-Only Hub Git, Reduced `sciontool init` Capabilities and Visible Orphaned Agents

When `image_tag` is unset, a release build uses its own version as the tag of the bundled `scion-*` agent images, so a Homebrew or release install runs the images published for its release. Clones and fetches the Hub runs on its own host refuse SSH and scp-style repository URLs. `sciontool init` drops `CAP_NET_ADMIN`, including from the bounding set, once it has set up network controls. Each agent's authority state (`live`, `orphaned`, `revoked` or `unrecorded`) is computed from its recorded delegation chain and shown in `scion list`, `scion look`, the web UI and the agent API. See [Orphaned and revoked agents](/scion/hosted/single-node/auth/#orphaned-and-revoked-agents).

## ⚠️ Breaking Changes
- **Downgrade floor raised to `nightly-20261112` (#4745):** Migration `0014_review_ladder` rewrites stored artifact grants (user write grants created by the removed review-only path on agent-owned artifacts become review grants), so `DowngradeFloor` moves from `nightly-20261009` to `nightly-20261112`. Self-update refuses targets older than the floor (`below_downgrade_floor`), including `v0.3.0`. Take a database snapshot before upgrading; see [Upgrading and Rolling Back a Hub](/scion/reference/hub-upgrade-rollback/).
- **Review joins the artifact grant ladder (#4745):** Grant levels are read ⊂ review ⊂ write ⊂ admin. Existing review grants now also give read access, including to people who could not read the artifact before; list them with `scion artifact grants <ref>` and remove any you do not want. The review-only grant path and the web UI's **Grant review access** flow are removed; owners, admin grantees and stewards give review grants through the normal grant path. See [People and projects (grants)](/scion/hosted/user/artifacts/#people-and-projects-grants).
- **Agent-written user secrets wait for owner approval (#4747, #4751, #4754):** A user-scoped secret an agent saves is held as pending and is not delivered to any agent until the owning user approves it with `scion hub secret pending approve` (or rejects it with `reject`), or from Profile → Secrets in the web UI, which shows each secret's state and the agent and project that saved it. Pending secrets are capped at 10 per agent and 50 per owner and expire after 7 days; owners are notified, `reveal` is audited, and every action records an audit event. Harness `capture-auth` scripts report a user-scope capture as pending approval.
- **Hub-scoped secrets reach agents only in `always` or `as_needed` mode (#4713):** Start and restart deliver a Hub-scoped environment secret directly only in `always` mode. An `as_needed` secret is filled only by the harness credential pass, and only for a key the harness asks for. Agent read paths list only `always` Hub-scoped environment secrets; admin reads keep the full view. The telemetry credential file is still delivered.
- **Secret Manager migration runs as maintenance and verifies values (#4729):** The `secret-hub-id-migration` maintenance migration (Admin → Maintenance) decodes each secret with the Hub's local key before writing it to GCP Secret Manager, reads it back to verify it, and keeps local copies until every secret is verified. Values an earlier run copied in encoded form are repaired, and a migration completed under an earlier release reopens once. `scion hub secret migrate` now refuses to run and points to the maintenance migration.
- **Runtime Broker Hub connections leave settings files (#4718):** Runtime Broker registration no longer writes `hub_connections` into settings. Each connection lives in the Runtime Broker credential store, and `hub_connections` keys are refused as not writable.
- **Hub-side git refuses SSH repository URLs (#4739):** Clones and fetches the Hub runs on its own host (shared-workspace provisioning at project create and clone, and the workspace pull) refuse an SSH or scp-style repository URL with `422` before any git work, with or without a project git credential. Use an HTTPS repository URL; a project git secret authenticates HTTPS only.
- **Chat permissions and the built-in `project-viewer` role (#4643):** Chat send, history, the thread list, promotion, uploads, and creating topics and group conversations are decided by chat access resolvers, and topic responses report each write action in `_capabilities` (`canPost` stays as an alias). A reader without chat post permission gets `403 chat_post_denied`. The new built-in `project-viewer` role can read a project and its chat but cannot post messages or create agents. An existing custom role named `project-viewer` is renamed `project-viewer-custom-<first 8 characters of its ID>` at startup (audited).
- **Release builds default agent images to their own version (#4660):** When `image_tag` is unset, a release build (`vX.Y.Z`, `-preview.N` or `-rc.N`) tags bundled `scion-*` agent images whose tag is `latest` or absent with its own version instead of `:latest`. Development, nightly and other builds keep `:latest`. Any set `image_tag` wins, and `image_tag: latest` opts out. The default is gated by `hub.image_tag_version_default` (server layer, on by default).
- **Telegram `downloads_path` retired (#4725):** Inbound Telegram attachments go through the Hub as uploads, and the Telegram plugin logs a warning and ignores a configured `downloads_path`.

## 🔐 Security & Access Control
- **`sciontool init` drops `CAP_NET_ADMIN` (#4636, #4727, #4728):** When a metadata server or the opt-in init firewall (`SCION_INIT_FIREWALL`) is set up, `sciontool init` applies the network policy itself and then drops `CAP_NET_ADMIN` from every capability set of every thread, including the bounding set, before the workspace clone, hooks, services and the harness start. A failed setup or drop refuses the start. `sciontool metadata status` reports the iptables check as not verifiable once the capability is gone.
- **Session generation in Hub JWTs and Conduit (#4741, #4752):** Hub user JWTs carry the user's session generation, checked on validation. Conduit sessions and streams authenticated with a Hub user token keep the generation they were admitted with and compare it on every re-check, so revoking a user's sessions also ends them.
- **Separate content host for shared artifacts (#4648, #4661):** The opt-in `server.hub.content_url` gives the Hub a second public origin that serves only artifact share links and artifact views. On that host every other route answers `404` before authentication, and cookies, `Authorization` and other credentials are stripped. The value must be `https` with no path, is admin-only, applies without a restart and is audited. A value on the Hub's registrable domain is refused on save and ignored at runtime unless `server.hub.content_url_allow_same_site` is set; the server config response and page report `content_url_status`. See [Server configuration](/scion/reference/server-config/).
- **Upstream and Runtime Broker text kept out of client responses (#4679, #4699, #4742, #4674):** Text from OAuth and OIDC endpoints, the Teams token endpoint and Google credential validation reaches errors and logs only through a 512-byte capped, sanitized wrapper. GitHub App token errors and template and harness-config validation failures return fixed client text. API clients see a Runtime Broker failure as its status and error code, with only allow-listed details relayed; the broker's own text is logged once, capped and sanitized. A caller-supplied chat topic key is logged at most 128 bytes long.
- **Per-peer keys for relay peers (#4412):** Relay peers can be enrolled with their own Ed25519 keys in `server.hub.conduit.peers`, with a private key in `server.hub.conduit.peer_key_file`. A signature verifies only with a key enrolled for the peer it names. Opt-in.
- **Workspace files API (#4690, #4740, #4688):** The Hub's workspace files API refuses paths with a `.git` component, caps request bodies, and opens each parent directory in turn without following symbolic links, giving each refusal a named reason. `sciontool init` counts a workspace marker entry only when it is a real directory (judged without following links), and a name in another letter case only when it is the same directory as the marker.
- **Credential and secret lifecycle (#4697, #4698, #4703, #4721):** Auto-suspend of a stalled agent revokes its credentials, as manual suspend does. Progeny-shared owner secrets are decided once per request on the owner-material chain, and a legacy chain with no recorded ancestry is withheld. A co-located flat Runtime Broker activation gets a fresh broker secret on every start. A project-default GCP passthrough identity goes through the same authorization and local-runtime checks as explicit and Hub-default identities.
- **Secret values kept out of Podman's command line (#4673):** Secret values are passed to `podman` through its environment instead of `-e KEY=VALUE` arguments readable from `/proc/<pid>/cmdline`, and rootless Podman's pause process is started first without them.
- **Rebuild, skills and repository probes (#4642, #4692, #4696, #4709):** Both rebuild executors reject a branch name with a leading dash or one that `git check-ref-format --branch` does not return unchanged, and rebuild requests validate it before a run is created. Skill version reads by number return only published and deprecated versions unless the caller can update the skill. Start-time repository probes run through the host-side git door.
- **Plugin Hub credentials (#4704, #4641):** Plugin Hub credentials fail when the plugin's Runtime Broker row cannot be confirmed, and the plugin transport settings (`transport_mode`, `transport_audience`) are treated as Hub wiring keys, omitted from integration settings responses.

## 🤖 Agent Lifecycle & Workspaces
- **Orphaned and revoked agents are visible (#4761):** The Hub computes each agent's authority state (`live`, `orphaned`, `revoked` or `unrecorded`) from its recorded delegation chain on every read. An orphaned agent, such as a child whose parent was deleted, keeps running but is denied every request that needs its delegation. The state shows as an Orphaned or Revoked badge in the web UI, as `running (ORPHANED)` in `scion list`, as a cause line in `scion look`, and as `authority` on `GET /api/v1/agents/{id}`; Hub admins list affected agents with `GET /api/v1/admin/orphaned-agents`. The only remediation is to stop or delete the agent.
- **NFS volume health check on Kubernetes (#4647):** After the agent Pod is running and before the agent starts, the Runtime Broker checks each NFS volume from inside the container for being mounted, readable and, unless read-only, writable. A volume that fails three consecutive checks 5 seconds apart fails the start with `volume_unhealthy` in the `container_start` step.
- **Kubernetes matches Docker (#4676, #4695):** Agent container environment sources are applied in Docker's order (resolved auth, harness and telemetry environment, config environment, runtime keys; the later source wins), and Kubernetes keeps the runtime's start command.
- **Agent state and stop (#4715, #4717, #4702, #4675):** A requested stop ends the container at Exited (0) instead of 255, an agent at rest no longer shows a running container status, a create the Runtime Broker refused before making a container is finalized without waiting on the broker (so deleting it no longer hangs), and flat Runtime Broker agents whose container is gone after a start are reconciled.
- **Podman container IDs (#4671, #4672):** Runtime commands capture stdout and stderr separately, so a rootless Podman warning no longer ends up in the container ID, and a `podman run` whose output is not a full 64-character container ID fails and removes the container it may have created.
- **Kubernetes provisioning on squashed NFS exports (#4635):** Provisioning accepts a refused `chown` when the entry already has the desired owner.
- **Harness fixes (#4737):** muse-code agents fire their hooks again; the antigravity harness image moves to `agy` 1.5.4.
- **Held agents get no Hub notices (#4749):** While an agent is on hold, the Hub delivers no notices to it, and notices skipped during the hold are not delivered later.

## 💬 Chat & Messaging
- **Chat plugin attachments as Hub uploads (#4725):** Chat plugins can ask the Hub whether a sender may attach files, upload them as the sender's unsent uploads, and name them in inbound messages, so the Hub delivers them to each recipient's inbox. Telegram uses this; uploads are limited to about 2 MiB per message.
- **Message-bus plugin supervision (#4480):** The Hub supervises message-bus plugins such as Telegram and Discord, detects a lost plugin session, respawns or re-dials the plugin with backoff and replays its subscriptions. Health and `scion doctor` report the plugin as degraded while it recovers, and publishes to observer plugins are bounded.
- **Artifact grant notifications (#4646):** A grant request can set `notify`; after the grant commits, the Hub sends the named user one notification naming the granter, the level and the artifact, only from an interactive session, only when the grant raises the user's level, and within rate limits.
- **Chat search and A2A bridge (#4735, #4746, #4753):** Web chat search runs on a separate read-only database handle under a time limit (`503 SEARCH_TIMEOUT`) and Hub-wide and per-user caps (`429 SEARCH_BUSY`). The A2A bridge reads an agent's reply from the caller's own conversation, and with `reply_poll.enabled`, a federated user's reply from that user's own conversation.
- **Chat lookup faults answer `500` (#4659):** A store error during a chat topic or project lookup returns a generic `500` instead of "Thread not found"; a missing topic or project still returns `404`.

## ☁️ Runtime Brokers, Settings & Operations
- **Event stream timeouts (#4649):** `server.hub.sse.max_connection_age` (default `10m`), `server.hub.sse.heartbeat_interval` (default `30s`) and `server.hub.platform_request_timeout` bound events streams and Conduit sessions with jitter, and Cloud Run warns when the platform timeout is unset. Heartbeats that change nothing visible no longer emit status events, and auto-expose stops polling ports.
- **`hub env` and `hub secret` infer the project (#4714):** A bare `--project` on `scion hub env` and `scion hub secret` infers the directory's Hub project, else the `scion use` project, as `tunnel`, `ssh` and `ssh-config` do.
- **Update and maintenance fixes (#4653, #4748, #4691):** A successful binary update removes its download directory before the restart and marks its plugin staging as applied. The pre-update database snapshot uses its own read-only connection, so the Hub keeps serving requests. A config edit that needs an unreadable Runtime Broker record answers a retryable `503` and writes nothing.
- **Request handling (#4750, #4668, #4666):** The combined Hub and web server logs each request once, canceled requests stop remaining per-item permission checks, and the conversation consistency check runs off the message path with a 200 ms deadline and new indexes.
- **Onboarding and validation (#4716, #4706):** Onboarding reports `harnessesSeeded` from the harness configs the setup wizard lists, and operator-only substrate validation also covers the default profile.
- **Release pipeline (#4655, #4657, #4645, #4644, #4665):** `build-release-images.sh --channel-tag preview|stable` moves channel tags by digest and never moves `:latest`, Homebrew image jobs fail when a pushed image cannot be pulled anonymously, build version detection accepts only release tag forms, the single-node VM deploy builds release images with the release image driver, and image builds record pushed digests.
- **herdr plugin (#4719, #4730):** An optional plugin under `extras/herdr-scion` shows the current project's running agents as herdr panes, with attach and start actions and a paged dashboard.

## 🧪 Experiments & Groundwork
- **Multiple-choice decisions (#4726, #4743):** Behind `web.chat_choices` (alpha, off by default), agents send one or more multiple-choice decisions with `scion message --choices` or `--choices-file` and replace them with `--update`. Each answer becomes a Hub-minted `choice-response` message to the agent and a row in a permanent decision log, a prompt with several decisions is answered as one set, and sending choices puts the agent in waiting-for-input. Every prompt carries a Markdown copy of its decisions for surfaces without cards. See [Multiple-Choice Decisions](/scion/hosted/user/messaging/#multiple-choice-decisions-experimental).
- **Leave a project (#4712, #4732, #4731):** With `hub.project_self_leave` (alpha, off by default), a signed-in user can remove their own direct membership of a project with `scion project leave <project>` or from the web UI, which show what leaving changes and settle what happens to the caller's agents.
- **Welcome project (#4720):** Behind `hub.welcome_project` (alpha, off by default), a workstation setup wizard step installs the agent-team templates and the skills they use, pinned to commit shas, into a `welcome` project and, given credentials, starts a coordinator that greets its owner once. See [Welcome project](/scion/getting-started/onboarding/#6-welcome-project-optional-experimental).
- **Open-review publish warnings (#4710):** Behind `hub.artifacts_open_review_check` (alpha, off by default, needs `hub.artifacts`), review mode tells the Hub a review is open, and a publish that would overtake another person's open review of the current version answers `409 review_open`, naming the reviewers, until the publisher publishes anyway (force), which is recorded in the decision log.
- **Legacy Runtime Broker conversion (#4656, #4693, #4694, #4738):** With `hub.flat_runtime_brokers`, a legacy Runtime Broker's Overview tab shows a read-only conversion plan, and `scion runtime-broker convert` gains `--apply`, `--status` and `--rollback` for one instance on a remote-registration host or a co-located host (in stages around a server restart). Apply is journaled and resumable. Flat Runtime Broker instances with a `cloudrun` target can activate using only their own credentials file.
- **Cloud Run native identity decided by the Hub (#4663):** With `hub.cloudrun_native_identity`, the Hub decides for each Cloud Run dispatch whether the instance runs as a native identity, records it on the agent, refuses a dispatch it cannot decide and withholds GCP access tokens while a native identity is set. The Runtime Broker runs block mode as the configured block account and refuses passthrough and unsupported combinations.

## 🎨 Web UI
- **Pending user secrets (#4754):** Profile → Secrets lists pending secrets with their state and the agent and project that saved them, with approve, reject and reveal actions.
- **Server config page (#4642, #4639):** The server config page shows a read-only version and effective channel with a **Manage updates** link to Maintenance, and has inputs for `shared_dir_storage_class` and `shared_dir_size`.
- **Chat copy actions (#4654, #4664, #4689):** The message menu's "Copy link" is renamed "Copy link to msg", and "Copy link address" copies the URL of an `http`, `https` or `mailto` link in a message. Every copy action uses one guarded clipboard helper that shows a toast and no longer throws where the Clipboard API is unavailable.
- **Smaller fixes (#4650, #4686, #4682):** Artifact review text stays at 16px on touch screens so iOS does not zoom on focus, the agent detail page shows Unlimited for stored zero limits, and chat starts a new group header when the recipient changes.
