---
title: "v0.4.0-preview.4"
---

Released on 2026-11-27 (`v0.4.0-preview.3..v0.4.0-preview.4`, changes since `v0.4.0-preview.3`).

`v0.4.0-preview.4` retires the `variable` secret type in favor of `on_demand` secrets that are never delivered at start, renames the message modes to `owner`, `direct` and a new `tree`, and moves the in-agent secret commands into `scion secret`. Those migrations raise the downgrade floor to `nightly-20261126`. `scion start` no longer resumes an existing agent. Hosted Hubs refuse development shortcuts and unbounded imports, project settings are deny-by-default, project pre-start hooks need a dedicated permission, and lifecycle hooks get a filtered environment. Recurring schedules get limits and can be run on demand. Experimental agent-scoped secrets, execution containers, the Inbox, per-agent usage tracking, never-suspend agents and cross-broker move bundles also land, and a suspended agent's last terminal screen is kept by default.

---

## Highlights

### 1. `on_demand` Secrets Replace `variable`, and Agents Get Their Own Secrets

The `variable` secret type is gone. Project- and agent-scope `variable` secrets become `on_demand` secrets, which are never delivered to a container at start, restart or harness credential gathering; an agent fetches one when it needs it with `scion secret get --value KEY`. The in-agent `sciontool secret` commands move into `scion secret`. Behind `hub.agent_secrets`, secrets can be scoped to a single agent, set at create time with `--secrets-file`, and requested by an agent from a user through a card in chat. See [Secret Types](/scion/hosted/user/secrets/#secret-types) and [Security — Secret Types, Delivery Exclusion, and Shadowing](/scion/reference/security/#43-secret-types-delivery-exclusion-and-shadowing).

### 2. Message Modes `owner`, `direct` and `tree`, and an Explicit `scion resume`

`lineage` is now `owner` and `branch` is now `direct`, and the new `tree` mode lets agents in the same creation tree message each other. `server.hub.default_message_mode` sets the mode for new agents. `scion start` and `scion create` no longer resume a suspended or stopped agent of the same name; they are refused with `409 agent_exists_resumable` and you run `scion resume`. See [Messaging Authorization](/scion/reference/messaging-authorization/) and [`start` vs. `resume`](/scion/local/agent-lifecycle/#start-vs-resume).

### 3. Hosted Hub Lockdown, Recurring Schedule Limits and Run Now

A hosted Hub refuses dev auth and test login, fetches imports only from bounded `https://github.com/...` URLs, and refuses project templates and harness configs that shadow global names. A project's `.scion/settings.*` may only set project-scoped keys, project pre-start hooks need `project.manage_pre_start_hooks`, and lifecycle hooks no longer see harness-config environment. Recurring schedules get a minimum interval and a per-project cap, and `scion schedule run <id>` fires one once without changing its timing. See [Recurring schedules](/scion/reference/server-config/#recurring-schedules-serverhubschedules) and [Running a Recurring Schedule Immediately](/scion/hosted/user/scheduling/#running-a-recurring-schedule-immediately-run-now).

## ⚠️ Breaking Changes
- **Downgrade floor raised to `nightly-20261126` (#5205, #5458, #5523, #5531):** The trigger-owned exec run schema, the `variable` secret retirement and the message mode rewrite are migrations older binaries cannot run against, so `DowngradeFloor` moves from `nightly-20261121` to `nightly-20261126`. Self-update refuses `v0.4.0-preview.3` and earlier, and nightlies before 2026-11-26, as downgrade targets (`below_downgrade_floor`). See [Upgrading and Rolling Back a Hub](/scion/reference/hub-upgrade-rollback/).
- **The `variable` secret type is retired (#5531, #5583, #5600):** On startup, `project` and `agent` scope `variable` secrets and secret requests become `on_demand`, Hub integration secrets (chat integrations, GitHub App credentials, message broker plugins) become `internal`, and leftover `user`, `runtime_broker` and non-integration `hub` `variable` secrets and pending secrets are **deleted along with their stored values**, with one `WARN` line per row. Runtimes no longer stage `variable` secrets or deliver `secrets.json`. Declared secrets in harness configs, profiles, settings and templates accept only `environment` and `file`; a harness config that declares `type: variable` fails to load. A System One configuration that pointed at a deleted Hub `variable` key fails closed until recreated.
- **Message modes renamed (#5523, #5279):** `lineage` is `owner` and `branch` is `direct` (**Direct plus owner** in the web UI), and `tree` (**Tree plus owner**) is new. Stored values are rewritten on startup. The old names are rejected by the API, the CLI, template validation and `server.hub.default_message_mode` with an error naming the replacement. On an HA Hub, restart one replica after the rollout so rows written by older replicas during the mixed-version window are rewritten.
- **In-agent secret commands moved to `scion secret` (#5551):** `sciontool secret get`, `list` and `set` are now `scion secret get --value`, `scion secret list` and `scion secret set`. The old commands print the replacement and exit `1`.
- **`scion start` no longer resumes an existing agent (#5194):** Starting or creating an agent whose name belongs to a suspended, stopped or halted agent is refused with `409 agent_exists_resumable`. Run `scion resume <agent>`, delete the agent, or pick another name. Agents still created or provisioning, such as after `scion create`, or with a launch in flight, are still started or followed.
- **Retired `scion message` flags removed (#5417):** `--in`, `--at`, `--plain`, `--notify`, `--channel`, `--thread-id` and `--cc` no longer exist. Use `scion schedule create --in/--at` for delayed messages, `scion notifications subscribe` for notifications, conversation references instead of channels and threads, and body mentions instead of `--cc`.
- **Project settings are deny-by-default (#5592):** A project's `.scion/settings.*` may only set project-scoped keys. Hub-level keys such as `server.*`, `hub_connections`, `quotas`, `agent_secrets`, `broker_policy` and `default_*`, and unknown keys, are ignored with a warning, and writes to them are refused. The Hub's workspace file write, upload and delete APIs refuse `.scion` paths, as they already did for `.git`. See [Keys read from project settings](/scion/reference/orchestrator-settings/#keys-read-from-project-settings).
- **Project pre-start hooks need `project.manage_pre_start_hooks` (#5577):** Creating, updating, activating or deleting a project pre-start hook needs the new permission, which no built-in project role holds, so in practice Hub admins manage them. Project members can still list and read hooks. See [Pre-Start Hooks](/scion/hosted/user/pre-start-hooks/).
- **Lifecycle hooks get a filtered environment (#5185):** `pre-start`, `post-start`, `pre-stop` and `session-end` hooks no longer see variables from a harness config (`env`, `env_template`, `no-auth-env.yaml`, `harness_configs.<name>.env`); those go only to the workload. Interpreter, loader, shell and git override variables (such as `LD_*`, `PYTHONPATH`, `NODE_OPTIONS`, `GIT_CONFIG*`) are always withheld. Hub, operator and secret variables such as `GITHUB_TOKEN` are still passed.
- **Hosted Hubs refuse development shortcuts and restrict imports (#5233, #5255, #5286, #5565):** A hosted server (`--hosted` or `server.mode: hosted`) refuses to start with dev auth from any source and refuses `--enable-test-login`, except on a designated test Hub. Imports, discovery and harness-config reimports accept only `https://github.com/...` folder and archive URLs by default, refuse redirects, and are bounded (64 MiB and 2 minutes to download, 512 MiB unpacked, 256 MiB or 20,000 files written). A project template or harness config cannot reuse the name or slug of a global or built-in one (`409 global_name_reserved`). See [Sources a hosted Hub imports from](/scion/local/templates/#sources-a-hosted-hub-imports-from).
- **Recurring schedules have limits (#5275, #5398):** `server.hub.schedules.min_interval` (default `5m`, `0s` turns it off) refuses with `400` a cron expression that fires more often, and `max_active_per_project` (default `100`, `0` turns it off) refuses more active schedules with `429 quota_exceeded`. Limits apply on create, cron change, enable and resume; active schedules keep running, and a paused schedule that breaks a limit must be edited before it resumes.
- **Scheduled messages follow the strict target rule (#5188):** Creating a message event or schedule for an agent that does not exist, is deleted, has a mismatched `agentId`/`agentName`, or cannot be read and messaged by the caller fails with `404`. Resuming a paused schedule, or a `PATCH` that changes its payload, cron, time zone or type, fails the same way. See [Scheduling — Security & Authorization](/scion/hosted/user/scheduling/#security--authorization).
- **The Hub will not start on an invalid `server` section (#5076):** A `server` section of `settings.yaml` that fails to parse or decode stops startup with the error instead of being ignored.
- **Agent container hardening (#5401, #5404, #5354):** Docker and Podman agent containers run with `--cap-drop NET_RAW` in every metadata and network mode, so tools that need raw sockets, such as `ping`, no longer work. A Runtime Broker refuses any agent volume whose host source is or contains a Docker or Podman socket. Docker, Podman and Apple container brokers refuse `worktree-per-agent` on shared (`nfs`) project storage, as Kubernetes already did.
- **Identity and authentication tightened (#5229, #5650, #5161, #5308, #5312, #5114):** The Hub's own GCP service account, and a Runtime Broker's host service account, are refused as agent or project identities (`400 identity_reserved`); a startup scan marks matching rows failed. Agent tokens without a recorded, unrevoked credential are refused with `401 invalid_token`, and bearer authentication requires an access or CLI token type and an `exp` claim. Proxy authentication checks more at startup and refuses `--enable-test-login`. The A2A bridge `/metrics` endpoint requires authentication.
- **Re-registering an online Runtime Broker needs `--force` (#5373):** `scion runtime-broker register` on a Runtime Broker that is online is refused with `409` unless you pass `--force`. Join-token re-mints that keep settings are exempt.
- **Access constraint management needs `hub.access_constraints` (#5596):** The access constraint admin API and UI are behind the new `hub.access_constraints` experiment (off by default) and answer `404` while it is off. Stored constraints are still enforced, and the Hub logs a warning when they exist with the experiment off.
- **Narrower agent and clone permissions (#5604, #5587):** A full-role agent's `set_message_mode` works only on its descendants, not on itself or peers. Cloning a project needs `project.update` on the source. Changing an agent's image, by edit or `reincarnate --image`, and `reincarnate --harness` also need `agent.attach`.
- **Claude agents skip critical-path delete confirmations (#5519):** The Claude harness sets `CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS=1` by default alongside `--dangerously-skip-permissions`, so globbed `rm` and `rmdir` cleanups no longer stall unattended agents. Set it to `"0"` to opt out. See [Supported Harnesses](/scion/supported-harnesses/).
- **`hub.content_hash_v2` is on by default (#5652):** Template and harness-config hashes also cover each file's path and executable bit, so a rename-only or chmod-only commit changes the hash.

## ⬆️ Upgrade Notes
- **Before upgrading:** check for `user`, `runtime_broker` and non-integration `hub` `variable` secrets you still need, since startup deletes them. Replace `lineage` and `branch` in templates, `settings.yaml` and `SCION_SERVER_HUB_DEFAULTMESSAGEMODE`, and fix any `server` section that does not decode.
- **Scripts and automation:** replace `scion start` used to resume with `scion resume`, `sciontool secret` with `scion secret`, and the removed `scion message` flags. Metrics scrapers of the A2A bridge must authenticate.
- **Mutation audit retention (#5159):** The Hub now deletes mutation audit records older than `server.hub.audit_retention_days` (default `90`) every hour. Set it to `0` to keep them indefinitely.
- **Image and Runtime Broker order (#5246, #5314):** Docker and rootful Podman Runtime Brokers install metadata interception through a `sciontool netns-setup` sidecar. Update agent images before Runtime Brokers, and pin agent image tags to the Runtime Broker's release. See [Security — Credentials Propagation](/scion/reference/security/#45-credentials-propagation).
- **Access constraints:** Hub admins who manage access constraints turn on `hub.access_constraints`.

## 🔐 Security & Access Control
- **Delegation standing everywhere (#5316, #5349, #5340, #5353, #5307):** Agent delegation standing is checked at Conduit admission, relay rechecks, auth refresh and structurally on every credential route; delegation applies the project-scope rule to every grant type, and revocations at suspend recover from failures.
- **External identity checks (#5318, #5235, #5237):** Google service account tokens on the external bearer path must match `allowed_emails` when it is set, and for OIDC providers whose userinfo omits `email_verified`, such as Microsoft Entra ID, the Hub verifies the email from the ID token.
- **Safer file and asset serving (#5125, #5260, #5271, #5296, #5164, #5277, #5267, #5276):** Workspace and attachment file opens refuse non-regular files, static asset paths are normalized before routing, untrusted content is served with `Referrer-Policy: no-referrer`, and the chat attachment blocklist covers more Windows extensions.
- **Network and metadata hardening (#5426, #5412, #5435, #5418, #5419, #5259):** Metadata-server probes use deadlines and block IPv6. The Claude init firewall drops IPv6, pins the gateway and makes SSH opt-in, and no longer allows `statsig.anthropic.com`. Secret Manager errors other than not-found fail instead of being treated as missing.
- **Init firewall policy (#5459, #5501):** `server.broker.init_firewall` and the Hub-wide `server.hub.init_firewall` set the egress allowlist and SSH opt-in applied when an agent turns on `SCION_INIT_FIREWALL`; agents cannot override them. See [Hub Init Firewall](/scion/reference/server-config/#hub-init-firewall-serverhubinit_firewall).
- **Broker agent policy (#5569):** A Runtime Broker's global settings can set `agent_policy` with `allowed_image_prefixes` and `max_resources`, enforced on every agent's final configuration before its container is created; projects, Hub settings and environment variables cannot loosen it. See [Agent Policy](/scion/reference/orchestrator-settings/#agent-policy-agent_policy).
- **Trusted proxies for client addresses (#5403):** `server.trusted_proxies` also decides whose `X-Forwarded-For` the Hub trusts for per-IP rate limits and audit records; the Helm chart exposes it as `hub.trustedProxies`.
- **Hosted explicit workspaces are contained (#5599):** On a hosted Runtime Broker, an explicit workspace path must sit under a root from broker-global or structural settings, never from project settings.
- **Smaller hardening (#5132, #5142, #5305, #5375, #5399, #5395, #5384, #5389, #5135, #5265, #5250):** sciontool's `gh` wrapper keeps a caller's `GH_TOKEN`. Project member views list only readable groups, notification streams send each user only their own events, project-scoped agent reads return `404` when access is denied, and agent config `PATCH` merges `env` by key and needs attach permission. Default GitHub App token permissions are intersected with what the App was granted.

## 🤖 Agent Lifecycle & Workspaces
- **Last terminal screen of suspended agents (#5304, #5410):** With `hub.suspend_screen` (alpha, on by default), the Hub captures an agent's visible terminal when it is suspended; `scion look` shows it, and the web terminal offers **Resume** and reconnects automatically.
- **Waking and resuming (#5141, #5612, #5422, #5407, #5462):** A decision response wakes an agent the Hub suspended, and a message that wakes an agent arrives together with the resume instruction as one input. Resume and restart prompts carry the earlier completion status, an agent started without a prompt moves to idle once ready, and suspending an already-suspended agent succeeds.
- **Clearer suspend and stop notifications (#5171, #5234, #5242, #5115):** An auto-suspended agent's notification names the reason and threshold, and an agent's creator is notified when someone else suspends or stops it.
- **Status accuracy (#5129, #5131, #5291):** The stall cutoff is longer while an agent is thinking, and an agent-set `ask_user` keeps the agent waiting for input until its turn ends.
- **Scheduled agents act as their creator (#5103):** An agent created by a `dispatch_agent` schedule or event is owned by the schedule's recorded principal, with the ancestry, default role, environment and secrets an interactive create would give it, from each schedule's next fire.
- **Starts and Runtime Brokers (#5063, #5154, #5138, #5174, #5109, #5061, #5112, #5123, #5113):** A start claim is released when dispatch fails early, a deregistered Runtime Broker returns a terminal `broker_deregistered` error, a running container is reused only if its `agent_id` label matches, and `--broker` accepts unique name and slug prefixes. Cloud Run Instances default to 2 vCPU and 2 GiB and start agents in their workspace.
- **Provenance (#5327, #5423, #5430, #5365):** `scion whoami` and `scion list` show each agent's image, generation, harness and model, agents record the template source URL and commit they were created from, and `scion doctor` reports image capabilities and version skew.
- **Kubernetes service accounts on flat Runtime Brokers (#5175, #5182):** With `create_service_accounts` set on a runtime entry or flat instance, the Runtime Broker creates the Kubernetes service account for a Hub-minted GCP service account; flat Kubernetes instances accept Workload Identity targets.

## 💬 Chat, Messaging & Schedules
- **Honest delivery status (#5104, #5058, #5440, #5508):** A message to an agent that is not running is marked **Agent unreachable**; **Accepted** means the runtime buffered it and **Seen** that the agent read it, and stuck pending messages expire after 10 minutes. Chat shows **Delivered** once the agent's Runtime Broker confirms delivery.
- **`scion conversation watch` (#5310, #5400, #5414):** Waits for new messages in a conversation, once or as a stream, with retries and NDJSON output. It is gated by `hub.conversation_watch` (alpha, on by default). See [Receiving Replies](/scion/hosted/user/receiving-replies/).
- **Schedules follow deleted agents and run on demand (#5360, #5409, #5535, #5552, #5428):** Deleting an agent cancels pending one-shot events that target or were created by it and pauses recurring message schedules that target it. `scion schedule run <id>` and **Run now** fire a recurring schedule once. An exec schedule can opt in to capturing JSON output up to 64 KiB.
- **Conversations (#5335, #5466, #5492):** Adding a participant accepts a user's email or handle or an agent's name, and `scion conversation list` and similar commands take `--limit` and `--all` and report truncation.
- **Graduated (#5644, #5649, #5643, #5554):** Scheduled send in web chat, starred messages, `gs://` links and the filter query language are always on; `web.chat_scheduled_send`, `web.chat_starred_messages` and `web.gcs_links` are retired. See [Filter Queries](/scion/reference/filter-queries/).
- **Smaller fixes (#5450, #5378, #5356, #5388, #5074):** Messages can carry only attachments, bare numbers and hex strings are no longer read as mentions, and chat keeps session and commit prefixes and links `gs://` paths.

## ☁️ Settings, Templates & Operations
- **Template import from a URL (#5239, #5153, #5024, #5216, #5377):** `scion templates import-url <github-url>` imports templates from a GitHub folder on the Hub. `scion templates delete`, `sync`, `push` and `update`, and `scion harness-config sync` and `push`, take `--scope`, and an ambiguous delete is refused. See [Importing templates from a GitHub URL](/scion/local/templates/#importing-templates-from-a-github-url-through-the-hub).
- **Hub branding (#5088, #5158, #5170, #5284, #5231, #5252):** Hub-wide branding takes effect across the web app and CLI sign-in page, with an admin branding page, corner style and `server.hub.branding.font_sans`.
- **Daily automatic Hub updates (#5461, #5486, #5525, #5526):** Admins can turn on daily automatic updates from **Admin > Maintenance**, with a selectable UTC start hour; `update_policy: auto` now installs at most once per day. See [Daily Automatic Release Updates](/scion/hosted/single-node/hub-server/#daily-automatic-release-updates).
- **Agent creation inputs (#5137, #5487):** `scion start` and `scion create` reject invalid agent names and labels with empty values, and file secrets are masked on the create form.
- **Smaller fixes (#5151, #5057, #5020, #5379, #5392, #5380, #5381, #5396, #5548, #5628, #5217, #5218):** `scion artifact publish --expires-in` sets retention at publish time, `scion harness-config show` includes capabilities, and `scion sa mint` takes `--json`. `/readyz` waits for the artifact store, template slugs resolve project, then user, then global, duplicate skills and templates get specific `409` messages, and Azure DevOps clone URLs are normalized.

## 🧪 Experiments & Groundwork
- **Agent-scoped secrets and secret requests (#5324, #5352, #5374, #5386, #5413, #5470):** Behind `hub.agent_secrets`, `scion hub secret ... --agent <name>` and the web UI manage secrets for one agent, agents can be created with `--secrets-file`, and an agent can request secrets from a user (`scion secret request`), who fills or dismisses the request in chat. Values are never shown back.
- **Execution containers and approved commands (#5348, #5510, #5524, #5567, #5634, #5654):** Behind `hub.exec_containers`, an agent can run the reserved `shell` harness with no LLM, so credentials signed in by hand stay in that container. With `hub.command_requests` too, an agent can propose a command for a named person to approve and run once in their execution container. See [Approved Commands](/scion/hosted/user/approved-commands/).
- **Inbox (#5427, #5476, #5463, #5467, #5478, #5465, #5481, #5518, #5534, #5576, #5616, #5618, #5648):** Behind `web.inbox_dashboard`, the Inbox gathers decisions, agents waiting for input, approvals, artifact reviews, secret requests and unread chats across projects; `scion inbox` prints a summary.
- **Per-agent usage tracking (#5594, #5606, #5646, #5664, #5647, #5635, #5641, #5642):** Behind `tokenomics.usage_ledger`, the Hub records model usage per agent, shown in an Agent Detail Usage panel and `GET /api/v1/agents/{id}/usage`. The `pi`, `grok-build` and `muse-code` harnesses report live usage, and harnesses describe their usage in a `usage.yaml` sidecar.
- **Lifecycle (#5517, #5561, #5623, #5656, #5460, #5589, #5549):** Behind `lifecycle.never_suspend`, an agent can be marked never-suspend; auto-suspend skips it and a manual suspend is refused unless a human forces it. Behind `hub.agent_move_bundle`, `scion reincarnate <agent> --broker <target>` carries the workspace and Agent home through Hub object storage. See [Never-Suspend Agents](/scion/local/agent-lifecycle/#never-suspend-agents) and [Transfer-mode ladder](/scion/hosted/ha/multi-broker/#transfer-mode-ladder-and---force).
- **Run limits and telemetry policy (#5621, #5655, #5622):** Behind `agent_policy.limit_ceilings`, admins set Hub-level `agent_limits` ceilings, and a create whose `max_turns` exceeds the ceiling is refused with `400 limit_exceeds_hub_ceiling`. Behind `agent_policy.telemetry_enforcement`, `telemetry.enforced` keeps projects from turning telemetry off.
- **Decisions (#5180, #5193, #5299, #5192, #5311, #5591, #5611, #5615):** Under `web.decisions`, decisions can offer an "Other" free-form answer or a single choice, and the decision log keeps offered and recommended choices. Behind `hub.decision_retention`, admins limit how long settled decisions are kept. See [Decision Retention](/scion/reference/admin-settings/#decision-retention).
- **Artifacts (#5119, #5624, #5661, #5662, #5571, #5581):** Behind `hub.artifacts_review_drafts`, in-progress reviews are saved as private drafts; behind `hub.artifacts_review_requests`, a publisher can ask specific reviewers to review; and behind `hub.artifacts_transfer`, a steward can transfer an agent-owned artifact to another agent they control.
- **Admin and access (#5144, #5480, #5240, #5251, #5273, #5333):** `hub.effective_permissions` adds an Effective permissions viewer, `hub.view_as_member` lets a Hub admin drop admin grants in their session, `hub.custom_default_user_role` lets `server.auth.default_user_role` name a custom role, and `hub.admin_managed_brokers` with `broker_policy.admin_managed_only` restricts agents to admin-managed Runtime Brokers.
- **Triggers, templates and mentions (#5108, #5219, #5338, #5334, #5458, #5536, #5300):** Behind `hub.github_triggers`, triggers evaluate CEL rules, post GitHub comments, handle push events, run exec actions and give dispatched agents an installation token. `hub.template_drift_warning` warns when a GitHub-sourced template changed upstream, and `hub.code_span_mentions` lets `` `@agent` `` notify like a mention.

## 🎨 Web UI
- **Navigation and layout (#5444, #5359, #5268, #5266, #5614, #5603, #5584):** Pages share breadcrumbs, the header has a Terminals dropdown at every width, and on a phone the terminal uses the whole screen; behind `web.terminal_key_bar`, terminal panes get a touch key bar.
- **Admin pages (#5566, #5570, #5366, #5485):** Admins can invite several users at once with project roles, GitHub App settings move to **Admin > Integrations**, System One providers have an admin page, and the Experiments tab filters by state.
- **Smaller fixes (#5202, #5257, #5106, #5211, #5213):** The Limits & Usage card shows inherited limits, status badges show agent-reported status, the UI backfills messages after an event-stream reconnect, and a thread's default agent stays current.
