Scion now mounts a repository's git metadata into agents so that an agent cannot change what git does for you or for other agents. On Kubernetes, git projects that share one repository across agents are no longer supported; use a clone-per-agent workspace instead.

---

## Highlights

### 1. Agents Get Read-only Git Metadata and a Private `.git/config`

For worktree-per-agent and shared-workspace git projects, Scion mounts the repository's git admin surface into the agent read-only — `.git/hooks`, `.git/info`, `.git/objects/info`, and other agents' worktree admin directories — and gives each agent its **own private, read-only copy of `.git/config`** in place of the shared one. The private copy has credential-bearing settings stripped and is pre-seeded so that `git push` and `git push -u origin <branch>` for the agent's own branch succeed without needing to write the config; personal git preferences go in the agent's own writable global git config, not the repository config. On the Apple runtime agents read the repository's git config directly; keep credentials out of repository git config (use a credential helper). See [Workspaces](/scion/local/workspace/#git-that-scion-runs-on-the-host).

### 2. Kubernetes: One Clone Per Agent for Git Projects

On Kubernetes, git projects that share one repository across agents — worktree-per-agent, or a shared-workspace project on NFS — are not supported. Create such a project as **clone-per-agent**, where each agent gets its own clone of the repository, or run it on a local or Docker broker. An agent whose project would share one repository is refused at start with a message naming the remedy.

:::caution[Upgrade note]
Before upgrading, commit and push work from Kubernetes agents in git projects on NFS shared workspaces.
:::
