Scion now mounts a repository's git metadata into agents so that an agent cannot change what git does for you or for other agents. On Kubernetes, git projects that share one repository across agents are no longer supported; use a clone-per-agent workspace instead.

---

## Highlights

### 1. Agents Get Read-only Git Metadata and a Private `.git/config`

For worktree-per-agent and shared-workspace git projects, Scion mounts the repository's git admin surface into the agent read-only — `.git/hooks`, `.git/info`, `.git/objects/info`, and other agents' worktree admin directories — and gives each agent its **own private, read-only copy of `.git/config`** in place of the shared one. The private copy has credential-bearing settings stripped and is pre-seeded (branch upstream plus `push.autoSetupRemote`) so a bare `git push` exits 0 — without the pre-seed a bare push fails with "no upstream branch". `git push -u origin <branch>` exits 0 and reaches the remote either way; git cannot persist the upstream (the private `.git/config` is read-only) and prints an `error:`, but the push still succeeds. Personal git preferences go in the agent's own writable global git config, not the repository config. On the Apple runtime agents read the repository's git config directly, and a shared-workspace git project is refused there (the per-agent private `.git/config` cannot be bound); keep credentials out of repository git config (use a credential helper). See [Workspaces](/scion/local/workspace/#git-that-scion-runs-on-the-host).

### 2. Kubernetes: One Clone Per Agent for Git Projects

On Kubernetes, git projects that share one repository across agents — worktree-per-agent, or a shared-workspace project on NFS — are not supported. Create such a project as **clone-per-agent**, where each agent gets its own clone of the repository, or run it on a local or Docker broker. An agent whose project would share one repository is refused at start with a message naming the remedy.

:::caution[Upgrade note]
Before upgrading, commit and push work from Kubernetes agents in git projects on NFS shared workspaces.
:::

### 3. Project `.scion` Mounted Read-only Needs an `agents` Directory

On Docker and Podman, a project `.scion` that Scion mounts read-only — one in a registered
outside-root checkout, one in a subdirectory of the workspace, or a nested `.scion` directory without
`agents/` inside the agent's own workspace (config-only agents) — must already contain an `agents`
directory. The runtime masks `.scion/agents` in the container but does not create it under a read-only
mount, so when it is missing the start is refused with a message naming the path. Create it once with
`mkdir <path>/.scion/agents` (`scion init` lists `.scion/agents/` in `.gitignore`) and start the agent
again.

A workspace in a subdirectory of a repository must be a registered git worktree of it; other
subdirectory workspaces are refused at start.
