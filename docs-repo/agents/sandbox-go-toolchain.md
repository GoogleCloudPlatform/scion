# Go builds, tests and lint in an agent container

- **Toolchain:** Go 1.26.11 everywhere (`go.mod`, `image-build/core-base/Dockerfile`, CI). `fmt-check` failures are real, often misaligned struct fields: run `make fmt` and confirm the diff is pure alignment.
- **extras modules** (`extras/*`) have their own `go` lines. Each Dockerfile's `golang` image must be at least that version; bump both together (`make check-extras-go-images`).
- **VCS status error** (`exit status 128`) in a worktree: add `-buildvcs=false`.
- **Running code at main's tip:** `main` is checked out elsewhere, so use a detached worktree: `git worktree add --detach /tmp/check <main-sha>`, then `git worktree remove --force /tmp/check`. For single files, `git show main:path`.
- **golangci-lint OOM (exit 137):** `GOGC=40 golangci-lint run --new-from-rev=main --concurrency=1 ./pkg/foo/... ./cmd/...`. `--new-from-rev=main` (or `--new-from-rev=<base-sha>` when local `main` is absent; when `GOCACHE` points at a shared mount such as `/scion-volumes/gocache`, never run `go clean -cache`, and pass `GOCACHE=/tmp/gocache-lint`—or `GOCACHE=/tmp/gocache-<slug>`, removed afterward, on shard builds—if concurrent eviction hits stale export data or missing cache files) shows only issues you introduced. Lint `./pkg/hub` itself in a separate run, as `hack/golangci-lint-split.sh` does in CI: `GOGC=40 golangci-lint run --new-from-rev=main --concurrency=1 --tests=false ./pkg/hub`. Not `./pkg/hub/...`, and not `--tests=false` on a combined run, which would stop linting tests in the other packages. With tests it compiles the whole test package. Its tests then get only `go vet`, through `make vet-hub-shard`. The hub run takes over 10 minutes, and CI lint fails on hub code, so run it in the background when you touch pkg/hub. After rewiring refactors or rebases that may leave pre-existing wrappers dead, `--new-from-rev` does not flag untouched definitions; run a scoped `--enable-only=unused` pass (`--tests=false` for `./pkg/hub`).
- **`make ci` and `make ci-full` compile the whole pkg/hub package** (`lint` runs `go vet ./...` and `test-fast` runs `go test ./...`, both with `-tags no_sqlite`). In a container, run the split CI uses instead:
  - **Core split & off-shard targets:** `make fmt-check lint-ci check-custom test-fast-ci build`, plus:
    - `make test-cmd-sqlite` when touching `./cmd` (note `cmd/doctor_platform_health_test.go` has no build tag, so `hub <-> hubclient` JSON-field parity tests such as `TestHealthSummaryClientTypeMatchesHub` already run in `test-fast-ci`; run `go test -buildvcs=false -run TestHealthSummaryClientTypeMatchesHub ./cmd` if skipping `test-fast-ci` when changing Hub HTTP response structs);
    - `make test-tz-contract` (`./pkg/hub/tzcontract`, outside the `pkg/hub` shards and `test-fast-ci`) when changing schedule, trigger, or HTTP authoring validation;
    - `make test-sqlite-nonhub` (or untagged `go test -buildvcs=false` on the touched package) when touching non-hub `!no_sqlite` packages (`SQLITE_NONHUB_PKGS` in `Makefile`, e.g. `./pkg/store/entadapter/...`, `./pkg/conduit/...`, `./pkg/ent/entc/...`, `./pkg/artifacts/...`), since `test-fast-ci` passes `-tags no_sqlite`;
    - `make test-fixture-coverage` (`./internal/fixturegen/...`, `!no_sqlite`, omitted from both `test-fast-ci` and `test-sqlite-nonhub`) plus `make ent-check` (regenerates `pkg/ent` in place; finish it before launching concurrent builds or tests) when changing `pkg/ent/schema`;
    - `make tidy-extras` (confirming clean `git diff extras/*/go.{mod,sum}`) plus `make vet-integration-extras` when root `go.mod`/`go.sum` changes or packages imported by `extras/*` (such as `pkg/hub` or `pkg/hubclient`) gain module dependencies (`extras/*` use `replace ../..` with separate `go.sum` files). When a `pkg/hubclient` interface or exported `pkg/hub` signature changes, also run `go vet -buildvcs=false ./...` inside each `extras/*` module that uses it (`grep -rl 'hubclient\.Client\|pkg/hub' extras`), since their test doubles and integration suites compile against it: `make vet-integration-extras` vets only modules with integration-tagged files, and passes while `extras/scion-a2a-bridge`'s `mockHubClient` fails to compile.
  - **Cross-package caller guards:** `./pkg/secret` (`go test -buildvcs=false ./pkg/secret`, `!no_sqlite`, `TestSecretBackendGet_CallersAreHubInternal`—skipped by `test-fast-ci`, so run it untagged when touching `pkg/hub`), `./pkg/util`'s `TestHostGitGoesThroughOneDoor` (already runs in `test-fast-ci`; if skipping `test-fast-ci` when adding or refactoring `exec.Command*` calls in `hostGitDoorRoots`, run `go test -buildvcs=false -run TestHostGitGoesThroughOneDoor ./pkg/util`), `./pkg/sciontool/rootexec` (already runs in `test-fast-ci`; if skipping `test-fast-ci` when adding or changing `exec.Command*` calls under `cmd/sciontool/` or `pkg/sciontool/`, run `go test -buildvcs=false ./pkg/sciontool/rootexec`—see `docs-repo/agents/sciontool-rootexec.md`), `./pkg/util/logging`'s `TestRequestPathSites` (scans `pkg/hub`, `pkg/artifacts`, and area dirs for `r.URL.*` reads; run `go test -buildvcs=false -run TestRequestPathSites ./pkg/util/logging` if skipping `test-fast-ci` when adding `r.URL.*` reads), `./hack/memsqliteguard` (already runs in `test-fast-ci`; if skipping `test-fast-ci` when adding `:memory:` SQLite opens, run `go test -buildvcs=false ./hack/memsqliteguard` and pin `PoolConfig{MaxOpenConns: 1}`), and `./cmd`'s `TestCapabilities_RegistrationMatchesHeartbeat` (run `go test -buildvcs=false -tags no_sqlite -run TestCapabilities_RegistrationMatchesHeartbeat ./cmd` when adding or changing a `BrokerCapabilities` field).
  - **Cross-shard `pkg/hub` lock-ins** (check these when running targeted hub shards instead of all shards):
    - Project-page, agent/chat list, or `LayerWeb` experiment response changes: locate and run `TestPerfBudget_AgentEndpoints` (`pkg/hub/perf_budget_test.go`, +1% response-byte budget—prefer opt-in `include=<token>` for bulky per-row fields—and `web/e2e-perf/budgets/fixture-schema.json` parity across `perfBudgetWebRequests`, including `GET /api/v1/experiments` for any experiment with `LayerWeb`; see `docs-site/src/content/docs/contributing/perf-tracing.md`, and in a container refresh via `env SCION_PERF_BUDGET_WRITE_WEB_SCHEMA=1 ./hack/hubshard/shard.sh postgres all "" TestPerfBudget_AgentEndpoints` inside the env-stripping wrapper (see **Leaked `SCION_*` env vars**) rather than unsharded `go test ./pkg/hub/`, then update `web/e2e-perf/budgets/fixture.mjs`) and `TestListAgentsLegacy_ResponseBodyMatchesGolden`;
    - `New()`-registered `requireExperiment` routes: add the experiment to `routeRegistrationExperiments` (`pkg/hub/experiments_helpers_test.go`) and, when it has `LayerWeb`, to the `want` map of `TestResolvedExperiments_WebLayerOnlyFromOneSnapshot` (`pkg/hub/experiments_test.go`), then locate and run that test;
    - Authorization catalog, routes, and bearer matrix: for new `authzop` catalog rows (or gating a catalogued route behind a default-off experiment), run `go test -buildvcs=false ./pkg/hub/authzop/...` (regenerates `.design/authorization-operation-catalog.md`) and locate and run `TestCatalogHTTPEntryPoints_LiveMethodCheck` and `TestBearerDispositionMatrix_CatalogEntryPoints` (`pkg/hub/bearer_disposition_matrix_test.go`); for new HTTP routes in `pkg/hub/server.go`, also locate and run `TestRegisteredRoutesHaveRouteMetadata`, `TestRegisteredRoutesHavePermissionClassification`, `TestCompressBypass_SensitiveResponsesFromCatalog`, and (for `RouteAgentToken` routes) `TestAgentStanding_CredentialRoutesCoverage`;
    - Permission, `UATScope`, or built-in role seed edits (`pkg/hub/permissions/registry.go`, `pkg/hub/seed.go`, `pkg/hub/test_admin_policy.go`): locate and run the lock-ins in `pkg/hub/{permission_registry,seed_roles,uat_project_relationship,test_admin_policy_census,test_admin_a3}_test.go` (under default/SQLite tags so `!no_sqlite` role and relationship tests run; note `web/src/components/shared/token-list.ts` `FALLBACK_SCOPES`, frozen AK1 `AgentScopes` such as `project:read`, and `testAdminPolicyDeny` blocking test-admin group delegation of built-in project roles);
    - AST dispatch, ceiling, reflection, and provenance guards: when moving external-effect/publish/render dispatch sites or adding ceiling, `Create*`, enum/format-validated `store.Agent` fields, or `agent.Phase` lifecycle reads in `pkg/hub`, locate and run `TestExternalEffectCallSiteClassification`, `TestReservedKeyStripCoverage`, `TestArtifactRefsStrippedAtEveryDispatchSite`, `TestHoldOrDispatchCallSites`, `TestRenderSites_ApplyAttachmentPlan`, `TestPersistedRowEffectEnumeration`, `TestUATIntrinsic_CeilingReadersUseHopCeiling`, `TestFixtureProvenanceCensus_CreateCallSites`, `TestListProjectAgentsSorted_MemberProjectionEquality` (`reflectFillStoreAgent`), and `TestAsyncStartPhaseReadsReviewed`.
  - **Postgres and SQLite parity:** when adding `*_Postgres` integration tests in `./pkg/ent/entc/`, `./pkg/testinfra/` or `./cmd/`, also add the pattern to `test-store-postgres-tail` in `Makefile` (explicit `-run` allowlists). SQLite uses a single-writer pool (`MaxOpenConns(1)`), so Postgres row-lock, `SKIP LOCKED` and advisory-lock contention are exercised only against Postgres (CI's T1 Postgres jobs or `SCION_TEST_POSTGRES_DSN` / `SCION_TEST_POSTGRES_URL`). In a container with `sudo`/`apt-get`, you can stand up a disposable local Postgres (`sudo apt-get update && sudo apt-get install -y postgresql`, then `/usr/lib/postgresql/*/bin/initdb -U postgres -A trust -D /tmp/pgdata` and `/usr/lib/postgresql/*/bin/pg_ctl -D /tmp/pgdata -l /tmp/pg.log -o "-p 5433 -k /tmp" start`, passing `SCION_TEST_POSTGRES_URL='postgres://postgres@localhost:5433/postgres?sslmode=disable&host=/tmp'` inside the env-stripping wrapper; container restarts wipe the rootfs). Run the full touched store package on both dialects (not just named tests): `make test-store-postgres-entadapter` sets `-timeout 60m` and fails any test calling `t.Skip` without `enttest.SkipOnPostgres`, so opt-in scale/benchmark tests must run a tiny smoke fixture by default. Import `pkg/store/enttest` (not `pkg/ent/enttest`, which panics with a nil driver), avoid raw `?` SQL placeholders in `enttest.NewClient(t)` tests (`SQLSTATE 42601` on Postgres), and ensure raw-SQL migrations invoked from `entc.AutoMigrate` probe first and execute zero parameterized `Exec`s on an empty schema (rejected by `enttest`'s Postgres `recordingDriver` snapshot). Because `pgx` switches cached prepared statements to a generic plan after 5 executions on one pool (and plain `EXPLAIN` with bound args never shows it), verify Postgres performance claims and plan shape from warm calls 7+ or under `plan_cache_mode=force_generic_plan`. In `pkg/hub`, `testServer`/`newTestStore` always uses in-memory SQLite even under `-tags integration` with `SCION_TEST_POSTGRES_URL` set—only `enttest`-backed fixtures switch to Postgres, and an `enttest: provisioned ephemeral postgres` log line is per-package/shard, not per-test, so verify the fixture's store opener before claiming Postgres coverage. Postgres `TIMESTAMPTZ` also keeps microseconds where SQLite keeps nanoseconds, so a store method that returns an in-memory `time.Now()` which callers compare with a later read must truncate it first (`time.Now().UTC().Truncate(time.Microsecond)`, as `pkg/store/entadapter/message_policy_store.go` does).
  - **Hub shard gates and container concurrency:** run `make vet-hub-shard SHARD=K`, `make test-hub-shard SHARD=K NOSQLITE=1` (the hub part of `test-fast`) and `make test-hub-shard SHARD=K` (default/SQLite tags—a targeted SQLite test list does not cover other `//go:build !no_sqlite` tests in the shard) for each shard holding a test you touched; new `pkg/hub/*_test.go` files calling SQLite helpers (`*_sqlite_helpers_test.go`)—and new test files in non-hub packages whose test helpers are `!no_sqlite`-tagged, such as `pkg/store/entadapter`—need `//go:build !no_sqlite`, or `make vet-hub-shard`, `go vet -tags no_sqlite`, and `NOSQLITE=1` fail. A change to non-test `pkg/hub` code or common `*_test.go` helpers can break a test in any shard (especially changes to shared authorization, identity, or standing helpers, where running all shards on both tag sets plus `make check-custom` is strongly recommended): when changing a `pkg/hub` signature or removing/renaming an exported struct field, grep `pkg/hub/*_test.go` for callers or `<Field>:` and run `make vet-hub-shard` on every shard with hits (map each hit by `-locate`-ing a `Test*` in that file; a hit in a common helper file, listed by `hubshard.sh -v`, compiles in every shard, so vet all shards), because `--tests=false` lint and targeted shard runs cannot see compile breaks in untouched shards; otherwise run every shard (`make test-hub-shards NOSQLITE=1`, `make test-hub-shards`, and `make vet-hub-shard SHARD=K` for each K from `hack/hubshard/hubshard.sh -shards`), or report which shards ran and leave the rest to CI. Adding an Ent entity grows every `pkg/hub` shard compile (~0.9 GiB/shard); if CI runner-shutdown kills cluster on one PR, check job logs for `Killed` or measure `make build-hub-shard` peak RSS rather than blindly rerunning. After a rebase, run `go build -buildvcs=false ./pkg/hub ./cmd/scion` before launching multi-minute hub shards to catch upstream compile breaks in seconds. Report which gates ran. Containers share a cgroup CPU cap (`/sys/fs/cgroup/cpu.max`, often 2 cores regardless of host `nproc`), and some harnesses cap single-command wall time (~7–15m), so pass `-timeout 20m` on large package suites (`./pkg/agent/...`, `./pkg/runtimebroker/...`, `./pkg/store/...`), split `make test-fast-ci` into two package batches if it hits the wall-time cap, keep hub lint and individual hub shards in separate background commands rather than one chained script, serialize heavy hub shard compiles/runs to 1 at a time on 2-core containers (2 concurrent runs still trigger OOMs or timing flakes in timeout-sensitive tests), avoid running heavy Go compiles concurrently with `golangci-lint` (which also takes a process lock), and finish `npm run build` and `make ent-check` before concurrent `go test`/`go vet` jobs.
- **pkg/hub tests run in shards.** The whole test package needs about 12 GiB to compile; never build it. `make test-hub-shard SHARD=K` (about 6 GiB; `NOSQLITE=1` for no_sqlite; `shard.sh test` rejects `-v` and prints non-verbose output plus a skip summary—use `shard.sh postgres` or a `-c` binary with `-test.v` for per-test lines), locate a test with `hack/hubshard/hubshard.sh -locate TestA TestB` (exact top-level names as separate arguments—not a single `"TestA|TestB"` regex or unsplit `$T` in `zsh`; a prefix matches nothing, and one name missing under `-tags` fails the whole call with no stdout; drive multi-shard loops from `bash` rather than `zsh` `set -- $spec`, quote globs like `--include='*.go'`, and brace revision vars as `"${H}:path"` so zsh does not parse `:w`/`:c` as history modifiers). Shards are computed from the current sources, so a test moves when files grow or after a rebase: locate again after editing tests (and separately in a base worktree before compiling a baseline binary), rather than trusting an earlier or briefed shard number, and keep test files unchanged while a shard compiles (its test-list check fails otherwise). For a targeted SQLite run without trusting a shard number, use `./hack/hubshard/shard.sh postgres all "" TestA TestB` (or pass `K` instead of `all`; pass space-separated exact test names, not `|` regexes like `go test -run`). `TAGS` only selects Go build tags; the `postgres` subcommand does not enable Postgres on its own. Which backend a test uses depends on its own gate: `enttest`-backed store tests require `TAGS="integration"` **and** `SCION_TEST_POSTGRES_URL` (with `integration` and only `SCION_TEST_POSTGRES_DSN` set, `enttest` silently falls back to SQLite; confirm real Postgres execution via `enttest: provisioned ephemeral postgres` in the log), whereas default-tag (`!no_sqlite`) DSN-gated tests (`requirePostgres`, `hubtestutil.RequirePostgresDSN`) connect to real Postgres under `TAGS=""` when `SCION_TEST_POSTGRES_DSN` is set (and do not print the `enttest` line). Pass whichever variable applies inside the env-stripping wrapper (run logs also label the actual tag set and whether `SCION_TEST_POSTGRES_*` is set; tests gated on `SCION_TEST_POSTGRES_*` skip, making the script fail, without their variable, and a missing named test also fails; redirect verbose output to `/tmp/<shard>.log 2>&1`). Alternatively, compile from `hack/hubshard/hubshard.sh -overlay /tmp/ov` with `GOGC=25 go test -buildvcs=false -p 1 -overlay /tmp/ov/overlay.json -tags hubshard,hubshard_K -run ... ./pkg/hub` (or `GOGC=25 go test -buildvcs=false -p 1 -c -overlay /tmp/ov/overlay.json -tags hubshard,hubshard_K -o /tmp/hubK.test ./pkg/hub` to compile once, then run from the package directory as `shard.sh` does: `(cd pkg/hub && PATH="$(go env GOROOT)/bin:$PATH" /tmp/hubK.test -test.paniconexit0 -test.run '^TestA$' </dev/null)`—passing `</dev/null` avoids PTY hangs if a test checks `term.IsTerminal`). For `pkg/hub` mutation checks, compile each mutant once with `-c` and run every targeted test from that binary instead of one `shard.sh` call per test, since a compiled binary never reflects later source edits; to check several production-code mutants with one compile, add them all in the scratch worktree before compiling, each behind its own value of an environment variable without the `SCION_` prefix that the env-stripping wrapper removes (`if os.Getenv("MUT") == "m1" { ... }`), run the binary once without it as a control and once per value (`MUT=m1 /tmp/hubK.test ...`), and confirm each value reaches its mutated code, since a surviving mutant may be unreached rather than untested; a new scratch `*_test.go` probe file gets its own shard, so re-run `-locate` before every `-c` build and confirm `--- PASS` or `-test.list` before trusting an exit 0 (`no tests to run` exits 0); never revert mutants with `git stash` (`refs/stash` is repo-wide—use `git checkout -- <file>` or remove the scratch worktree); a mutant in a test file or test double still needs its own compile, and `code-review` (Review Process step 2) owns when mutants may share a build; `-tags hubshard,hubshard_K` without `-overlay` still compiles every test file. Overlays snapshot shard-tagged `_test.go` files (plus generated shard-driver files) only, keyed to that checkout's absolute path—both production `.go` files and common helper `_test.go` files in `./pkg/hub` are read live—so regenerate the overlay after sharded test edits, generate a fresh overlay inside any scratch worktree, and pass caller test names to `-locate` when changing a shared helper. Inject store faults in `pkg/hub` tests with `installStoreFault` / `testServerWithStoreFault` (`pkg/hub/store_fault_helpers_test.go`), never by reassigning `srv.store` (`check-hub-store-reassign`). See `hack/hubshard/README.md`.
- **`-race` on pkg/hub** can OOM under a `ulimit -v` cap. Run targeted tests without `-race`, run `-race` uncapped, or use the nightly Race Detection workflow (`.github/workflows/race-detection.yml`): reporting-only, no_sqlite subset; SQLite-backed tests get race coverage only from an uncapped local run. On 2-core containers, a full SQLite hub shard under `-race` takes 75–110+ minutes; run individual suspect tests from a prebuilt `-race -c` shard binary instead (or pass `-test.timeout=120m` if a full SQLite `-race` shard is required).
- **Leaked `SCION_*` env vars:** an agent container sets dozens (`SCION_PROJECT`, `SCION_CREATOR`, `SCION_MODEL`, …). They affect config, cmd, hub and sync tests, and `SCION_MODEL` fails the hermes provision test in `make ci` (ptone/scion#6260). Strip them all (works in both `bash` and `zsh`, and when none are set): `bash -c 'unset "${!SCION_@}"; exec "$@"' _ make <target>`. Keep the `bash -c`: `${!SCION_@}` is bash syntax, so the bare `unset` in a `zsh` tool shell fails with "bad substitution" and ends the rest of a chained command. Never run `env` or `printenv` (or pipe them into `unset`) to strip variables—that prints container credentials into transcripts. That also drops intentional `SCION_*` test settings (`SCION_TEST_POSTGRES_*`, `SCION_PERF_BUDGET_WRITE_WEB_SCHEMA`); pass them inside the inner command (`env SCION_TEST_POSTGRES_DSN=... make <target>`).
- **Gitignored build output fails other gates.** `npm ci` (its postinstall), `npm run build` and Vite create `web/public/shoelace/`, which fails `TestRootLevelStaticFile_ListMatchesPublicDir` (ptone/scion#6979). From the repository root, run `rm -rf web/public/shoelace` before Go hub tests, and don't run a web build or Vite while Go hub tests run (or run web builds in a separate `git worktree` when executing Go hub shards in parallel). Don't remove `web/dist`: it holds the tracked `web/dist/client/.gitkeep`.
- **Shallow clones:** a clone-per-agent checkout may be shallow (`git rev-parse --is-shallow-repository`). Then `git diff main...HEAD` and `--new-from-rev=main` find no merge base, or a wrong one. Diff and lint (`--new-from-rev=<base-sha>`) against the base SHA named in your brief, or, where remote use is allowed, `git fetch --deepen=200 origin main` (or `git fetch --unshallow origin main` before full-history `git log -S` / `git blame`).
- **Latest main:** you cannot fetch from a worktree. Once the human has pulled into the primary checkout, `git rebase main` sees it. When fixing a test, check whether it already fails on main (detached worktree) so you fix the current version.
