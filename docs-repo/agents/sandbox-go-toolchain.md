# Go builds, tests and lint in an agent container

- **Toolchain:** Go 1.26.1 everywhere (`go.mod`, `image-build/core-base/Dockerfile`, CI). `fmt-check` failures are real, often misaligned struct fields: run `make fmt` and confirm the diff is pure alignment.
- **extras modules** (`extras/*`) have their own `go` lines. Each Dockerfile's `golang` image must be at least that version; bump both together (`make check-extras-go-images`).
- **VCS status error** (`exit status 128`) in a worktree: add `-buildvcs=false`.
- **Running code at main's tip:** `main` is checked out elsewhere, so use a detached worktree: `git worktree add --detach /tmp/check <main-sha>`, then `git worktree remove --force /tmp/check`. For single files, `git show main:path`.
- **golangci-lint OOM (exit 137):** `GOGC=40 golangci-lint run --new-from-rev=main --concurrency=1 ./pkg/foo/... ./cmd/...`. `--new-from-rev=main` shows only issues you introduced. Lint `./pkg/hub` itself in a separate run, as `hack/golangci-lint-split.sh` does in CI: `GOGC=40 golangci-lint run --new-from-rev=main --concurrency=1 --tests=false ./pkg/hub`. Not `./pkg/hub/...`, and not `--tests=false` on a combined run, which would stop linting tests in the other packages. With tests it compiles the whole test package. Its tests then get only `go vet`, through `make vet-hub-shard`. The hub run takes over 10 minutes, and CI lint fails on hub code, so run it in the background when you touch pkg/hub.
- **`make ci` and `make ci-full` compile the whole pkg/hub package** (`lint` runs `go vet ./...` and `test-fast` runs `go test ./...`, both with `-tags no_sqlite`). In a container, run the split CI uses instead: `make fmt-check lint-ci check-custom test-fast-ci build`, then `make vet-hub-shard SHARD=K`, `make test-hub-shard SHARD=K NOSQLITE=1` (the hub part of `test-fast`) and `make test-hub-shard SHARD=K` for each shard holding a test you touched. A change to non-test pkg/hub code can break a test in any shard: run every shard (`make test-hub-shards NOSQLITE=1`, `make test-hub-shards`, and `make vet-hub-shard SHARD=K` for each K from `hack/hubshard/hubshard.sh -shards`), or report which shards ran and leave the rest to CI. Report which gates ran. Each of these can take 10 minutes or more, and longer cold; start them in the background.
- **pkg/hub tests run in shards.** The whole test package needs about 12 GiB to compile; never build it. `make test-hub-shard SHARD=K` (about 6 GiB; `NOSQLITE=1` for no_sqlite), locate a test with `hack/hubshard/hubshard.sh -locate TestA TestB` (exact top-level names, several per call; a prefix matches nothing). Shards are computed from the current sources, so a test moves when files grow or after a rebase: locate again after editing tests, rather than trusting an earlier or briefed shard number, and keep test files unchanged while a shard compiles (its test-list check fails otherwise). For a targeted run, compile the shard from an overlay with `go test -run` (top of `hack/hubshard/README.md`); an overlay is a snapshot, so regenerate it after edits. See `hack/hubshard/README.md`.
- **`-race` on pkg/hub** can OOM under a `ulimit -v` cap. Run targeted tests without `-race`, run `-race` uncapped, or use the nightly Race Detection workflow (`.github/workflows/race-detection.yml`): reporting-only, no_sqlite subset; SQLite-backed tests get race coverage only from an uncapped local run.
- **Leaked `SCION_*` env vars:** an agent container sets dozens (`SCION_PROJECT`, `SCION_CREATOR`, `SCION_MODEL`, …). They affect config, cmd, hub and sync tests, and `SCION_MODEL` fails the hermes provision test in `make ci` (ptone/scion#6260). Strip them all: `env $(env | awk -F= '/^SCION_/{printf "-u %s ", $1}') make <target>`. That also drops the `SCION_TEST_POSTGRES_*` settings; set them again explicitly for Postgres tests.
- **Gitignored build output fails other gates.** `npm ci` (its postinstall), `npm run build` and Vite create `web/public/shoelace/`, which fails `TestRootLevelStaticFile_ListMatchesPublicDir` (ptone/scion#6979). `make build` (part of `make ci`) creates `build/`, which fails `web/src/utils/ci-web-checks-filter.test.ts` in `npm test`. From the repository root, run `rm -rf web/public/shoelace build` before the other side's gate. Any existing `build/` path counts, so `build/scion` alone is not enough; this also deletes the pinned golangci-lint in `build/tools/`, which `make golangci-lint` rebuilds. Don't run a web build or Vite while `make ci` runs. Don't remove `web/dist`: it holds the tracked `web/dist/client/.gitkeep`.
- **Shallow clones:** a clone-per-agent checkout may be shallow (`git rev-parse --is-shallow-repository`). Then `git diff main...HEAD` and `--new-from-rev=main` find no merge base, or a wrong one. Diff against the base SHA named in your brief, or, where remote use is allowed, `git fetch --deepen=200 origin main`.
- **Latest main:** you cannot fetch from a worktree. Once the human has pulled into the primary checkout, `git rebase main` sees it. When fixing a test, check whether it already fails on main (detached worktree) so you fix the current version.
