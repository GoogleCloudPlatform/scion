# Helm chart and Terraform gates in an agent container

Agent images ship `helm` and Go, but not `kubeconform`, `terraform` or a Postgres server. Install the versions CI pins under `/tmp`, never in the checkout. Report any gate you could not run.

- **kubeconform:** use the version `.github/workflows/chart-ci.yml` installs (v0.6.7 today): `GOBIN=/tmp/bin go install github.com/yannh/kubeconform/cmd/kubeconform@v0.6.7`, then put `/tmp/bin` first on `PATH`.
- **Chart (`deploy/helm/scion-hub/`):** run `bash deploy/helm/scion-hub/tests/run-all.sh`, which also runs `hack/verify.sh`. Call `verify.sh` alone only by absolute path: it changes into the chart directory and then greps `$0`, so a relative path fails its own pipeline sweep. Exit 2 is a meta-failure (for example a missing `kubeconform` or `helm`), not a pass. Read the exit status directly: piping into `tail` reports `tail`'s status. For a hand-run `helm template | kubeconform`, quote the resource count (`VALIDATION.md`).
- **Terraform (`deploy/terraform/`):** use `TF_VERSION` from `.github/workflows/terraform-ci.yml` (1.9.8 today), downloaded from `releases.hashicorp.com` and checked against its `SHA256SUMS`. Run the workflow's steps: `terraform fmt -check -recursive` in `deploy/terraform`, then `terraform init -backend=false -input=false` and `terraform test` in each root and module with `tests/`. Use a scratch copy (`mkdir -p /tmp/tf && git archive HEAD deploy/terraform | tar -x -C /tmp/tf`), because `.terraform/` and `.terraform.lock.hcl` are not gitignored, and set `TF_PLUGIN_CACHE_DIR` under `/tmp` to download providers once. Test at the pinned version: a newer Terraform can fail differently on the same test (for example, 1.9 applies `override_resource` values only at apply, not in `command = plan`).
