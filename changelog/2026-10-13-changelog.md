# Release Notes (2026-10-13)

The CLI's local-only mode is gone: every command now requires a Hub. Async agent launch became the `hub.async_agent_launch` experiment, with per-step progress, typed failures and web support. User access tokens now need matching selectors for chat, quota and agent operations. A fix restores agent starts on co-located Hubs that refused every start after an upgrade.

## ⚠️ BREAKING CHANGES
* **A Hub is always required** (#3423, #3542, #3510): With no Hub configured, every command prints a one-line `no hub configured` error. `--no-hub`, `hub enable` and `hub disable` are hidden and print an error. Templates commands no longer fall back to local silently. A project's Hub project ID comes only from its own settings, never the global settings. `hub shadow` and `hub unshadow` are removed in favor of `scion use`, and existing shadow directories still resolve with a notice.
* **Async launch is an experiment** (#3620): `server.hub.async_agent_launch` and its env var are retired and ignored, and an admin PUT with the key gets 422. Hubs that set it create synchronously until the `hub.async_agent_launch` experiment is enabled.
* **Token selectors for chat, quota and agent operations** (#3550, #3475, #3473): Chat writes by a user access token need `inbox:write`, and reads of the caller's own DMs, read state and preferences need `inbox:read`, within the token boundary. Quota administration needs the new `quota:*` selectors. Agent PATCH, workspace sync, stop-all, port registration and message mode need their matching `agent:*` selectors. Runtime Broker settings writes are authorized by the keys they change.
* **Template config is file-only** (#3558, #3516): Template create and PUT reject a config body (400 `template_config_in_file`) and an image (400 `template_image_not_supported`), and PUT is metadata-only. The Hub no longer copies a template's image, env or telemetry into an agent's inline config. `admin validate-resources` lists stored configs.
* **Project delete refused while agents remain** (#3538): Project delete answers 409 while the project has agents whose runtime deletion is not confirmed, listing them. Use `?force=true` or `scion hub projects delete --force`.
* **Agents need `--self` to remove themselves** (#3533): Inside an agent container, `scion delete` and `scion stop --rm` refuse to remove the current agent without `--self`, and `scion stop --all --rm` skips it.
* **Workstation system routes need Hub admin** (#3587): Mutating `/api/v1/system/*` workstation routes require a Hub admin. *(Contributor: Stephen Ierodiaconou)*
* **One `--test-mode` for test Hubs** (#3467): `--test-mode=off|member|admin|super-admin` replaces the three test-identity startup flags, and is refused with `--production`.

## 🚀 Features
* **Async launch progress** (#3429, #3590, #3379, #3600, #3524, #3603, #3381): Kubernetes launches report steps (scheduling, awaiting capacity, image pull, container start, sync, startup gate) and typed failures. The web create form uses the async path, showing the launch step while provisioning, and an incomplete create's code and reason with Delete and Create again. Runtime refusal causes (`runtime_forbidden`, `runtime_unauthorized`) reach the API, CLI and web. Succeeded launches apply the Runtime Broker's resolved image and harness config. Cloud Run sandbox joins async launch, and both Cloud Run runtimes fall back to synchronous creates.
* **Project thread groups, experimental** (#3513, #3576, #3579, #3514): Behind `hub.chat_thread_groups`: a `/api/v1/thread-groups` API with events, chat rail groups backed by the API, `scion conversation group` commands, and a sweeper that migrates each user's personal thread groups.
* **`scion vscode`** (#3562, #3495, #3568, #3594): `scion vscode <agent>` opens VS Code Remote-SSH on an agent with a pinned host key, without editing `~/.ssh/config`. `scion tunnel`, `ssh` and `ssh-config` use the `scion use` context. Tunnel and web-terminal streams deliver interval renewals to the target.
* **Declarative harness ready and delivery** (#3520, #3583, #3619): Harness configs gain `ready` and `delivery` blocks. Readiness gating reads each harness's ready spec instead of a hard-coded table, and message submission follows the delivery spec.
* **Settings** (#3613, #3610, #3528, #3536, #3455, #3606): The save report lists channels and federation keys saved but not applied under `reload.skipped`. Admin settings report the source actually applied. Profiles edited in the admin UI apply to the next start on every DB-backed Hub, SQLite included. Configure clears (limits, thinking level, resources, system prompt, env keys) reach the next start. The workstation Runtime Broker host is editable. `check-image` looks in local image stores before the registry.
* **Telemetry** (#3505, #3627, #3607, #3592): OTLP exports support client certificates (`telemetry.cloud.tls.cert_file`/`key_file`) with rotation, applied consistently to the server log bridge. Server Config gains switches for the Hub's own metrics and trace export. Telemetry and log labels follow the applied Hub name.
* **Notification delivery** (#3480, #3624, #3497, #3566): Failed agent notification deliveries are retried for up to 24 hours instead of being marked dispatched. Notifications record an attempt count and a delivered or failed outcome. Each channel stays paired with its own config. With a Runtime Broker set, user notifications go through it only, so they no longer arrive twice.
* **GitHub credentials for imports** (#3484, #3618): Template and harness-config imports and skill discovery use the `GH_{OWNER}__{REPO}` / `GH_{OWNER}` credential cascade at project, Hub and user scope, as do `scion harness-config install` and `scion templates import`.
* **Agent launchers** (#3529, #3398, #3530, #3572): An agent can read the status of any of its descendants. A launcher's lasting 404 is no longer reported as a deletion. `scion start` no longer deletes an agent whose start outcome is unknown. Hub-mode `scion create` sends the `--config` file.
* **Flat Runtime Brokers, phase 3, experimental** (#3525, #3552, #3488): Each flat instance gets its own settings policy, with `runtime_target` infrastructure inputs and `agent_defaults` workload defaults.
* **Artifacts, experimental** (#3586, #3570, #3490, #3485, #3502, #3508, #3611): `scion artifact view`, `list` and `grants`. Link lifetimes and a create capability. Share dialog and Move fixes. HTML bundles render in the chat preview through the sandboxed view. Agent starts warn when artifact scopes are dropped.
* **CLI and web** (#3511, #3521, #3554, #3569, #3359, #3442, #3597, #3424, #3415): `hub list --check` verifies auth per Hub, and `scion use` lookups name Hubs it could not search. Server and Runtime Broker commands accept `--hub` nicknames. An explicit `--project` beats `SCION_PROJECT_ID`. The GCP identity pickers offer Block for Kubernetes targets. Per-profile default identities warn when unmapped. Bulk reset-auth reports a stable code per failure. Maintenance actions show failures as toasts and group completed migrations.
* **Groundwork** (#3598, #3537, #3532, #3471, #3602): Peer-Hub federation tokens and a non-member `project-visitor` role behind `federation.project_visitors` (default off). Test identities on another test Hub through target-Hub profiles. A host-owned per-agent state file and a Runtime Broker delete mode for soft-deleted agents' retained files, not used yet.

## 🔒 Security
* **Uniform agent-token refusals** (#3563, #3420): Every refused agent token gets the same 401 body, with the cause only in the server log. Agent-token checks read less and throttle `last_seen_at` writes.
* **Event payload scoping** (#3588): Image-build output is published only to the requesting user's subject, and build requests need a user identity. Invite and other events carry minimal payloads.
* **Server secrets** (#3584, #3512, #3437): `SESSION_SECRET` is deprecated in favor of `SCION_SERVER_SESSION_SECRET` (still read, with a warning). Server secrets are kept out of agent env passthrough. `scion server start` prints the dev token file path instead of the token. Agent credential files are read with no-follow, size-bounded reads.
* **Last-admin and sign-in audit** (#3435, #3407, #3457, #3443): The last-admin check covers binding replacement, nested groups and scheduled constraints. Sign-in refusals on the web, proxy and resolver paths are audited. Identity resolution returns store errors instead of provisioning on a failed lookup.

## 🐛 Fixes
* **Co-located Hubs accept starts again** (#3622): An empty stored runtime catalog no longer hides the settings file's profiles, so co-located Hubs no longer refuse every new agent with "available profiles: none" after an upgrade.
* **Claude folder-trust dialog** (#3395): The provision manifest records the in-container workspace path, so Claude Code no longer shows its folder-trust dialog and blocks. *(Contributor: Stephen Ierodiaconou)*
* **Starts and dispatch** (#3599, #3601, #3427, #3396, #3595, #3565): A sync create's start no longer ends when the Hub stops waiting, so slow Kubernetes cold starts no longer lose their pod. A Runtime Broker 409 is relayed as 409 instead of 502. A `not_launched` end leaves the start claim to its holder. Superseded starts are awaited before name-addressed work. Kubernetes workspace-provision failures show their log tail. Cloud Run reports attach as unsupported.
* **Hub startup and shutdown** (#3523, #3522, #3626, #3625, #3614): Off Google Cloud, the Hub skips GCP project ID auto-detection instead of waiting about 13 s *(Contributor: Stephen Ierodiaconou)*. Shutdown waits for Runtime Broker work before closing the store. Concurrent AutoMigrate calls no longer crash. A non-level `level` attribute no longer panics the logger. Long image-build log lines no longer wedge later builds with 409.
* **Agent status hooks** (#3609, #3540, #3534): Sub-agent-held waits survive the parent's Stop and tool-start, and the parent's own question nests inside them. A parent Notification no longer overwrites `limits_exceeded` or `crashed`.
* **Agent files and projects** (#3494, #3426, #3436, #3404, #3507, #3585, #3539, #3573): Per-agent JSON files are synced to disk around rename. Kept stale agent directories are removed after the soft-delete retention window. `scion delete` finds agents in the external layout and no longer falsely deletes a global-only name. Project init picks its layout from the target directory. A provider path ending in `.scion` is used as is, and leftover configs are orphaned for prune only on positive evidence.
* **Other** (#3506, #3596, #3615, #3574, #3553, #3499, #3580, #3500): Completed scheduled events are purged 7 days after they finish, whatever the soft-delete retention. The template snapshot backfill no longer rolls back a racing edit. A relative `auth.dev_token_file` resolves against `~/.scion`. Cloud Run sandbox state is safe under concurrency and records starting entries. Agent runtime templates check the serve health probe. Telegram v1 reconfigure keeps poll loops separate.

## 🔧 CI & Infrastructure
* **CI** (#3493, #3543, #3549): Go build caches are per workload and saved only on pushes to main, with the `pkg/hub` shards sharing one cache. The repo hero image shrinks and release checkouts are blobless.

## 📖 Docs
* **Guides** (#3560, #3581, #3518, #3557, #3582, #3564): A new Using Artifacts guide with a walkthrough follow-up and HTML rendering in publish help. A new Working with several Hubs page. Helm notes on leftover cluster-scoped RBAC objects. `scion message --attach` help qualifies warnings.
