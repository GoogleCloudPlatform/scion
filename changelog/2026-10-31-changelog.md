# Release Notes (2026-10-31)

This day hardened the Hub and Runtime Broker trust boundaries. Hub-Runtime Broker connections now require TLS off loopback, host-side git no longer touches host credentials, and template and Agent home files stay inside their directories. It also added experimental chat retention and held-edit re-checks, and let Runtime Brokers without Google Cloud credentials bootstrap hub-managed workspaces.

## ⚠️ BREAKING CHANGES
* **Hub-Runtime Broker transport policy** (#4384, #4404): The Hub and the Runtime Broker both refuse plaintext connections to non-loopback endpoints. Runtime Broker secrets and join tokens are minted only for requests that arrive over TLS or from the same host. Forwarded headers are taken only from trusted proxies, and the relay public listener is checked the same way. When `server.trusted_proxies` is unset, a proxy on the same host (127.0.0.1, ::1) is trusted, with a startup warning. An explicit list, including `[]`, is used exactly. Refusals name `server.trusted_proxies` in the 403 details, the Hub error and the Runtime Broker log, and also raise a health and doctor finding. Deployments with a plaintext non-loopback hop must move to TLS.
* **Host-side git remote commands use no host credentials** (#4387): Git remote operations that the Hub or a Runtime Broker runs for a project no longer use the host's credential helpers, askpass, `~/.netrc`, TLS client certificates, Kerberos credentials or ssh identity. Without a project git secret they run anonymously. With one, only that secret is used.
* **Explicit project paths need a `.scion` directory** (#4401): A Runtime Broker given an explicit project path now requires a `.scion` directory or marker inside it, and refuses a `.scion` that is a symlink pointing outside the path. Without one, agent create, start and restart fail with 409 `project_path_not_initialized` instead of mounting the path's parent as the workspace.
* **Template content files stay inside the template directory** (#4400): `agent_instructions` and `system_prompt` files must be regular files of at most 4 MiB inside the template directory. Symbolic links are not followed. A single-line value must be a relative path, and a value with a line break is inline text. A file that exists but can't be read this way is now an error that explains the fix. It is no longer treated as inline text.
* **GitHub App tokens only for the agent's own project** (#4397): On create, start and restart, the Hub mints App installation tokens only for the agent's own project. An agent whose project has no installation gets no App token.
* **Agent pods don't mount a Kubernetes API token** (#4362): Agent pods are created with `automountServiceAccountToken: false` in every GCP identity mode. Workload Identity is unaffected, and pods keep their ServiceAccount.
* **Placement checked across runtimes and profiles on save** (#4415): Saves now check placement across entries (non-Kubernetes runtime, missing runtime entry, pool conflict). A problem the save introduces is refused with 422, and a problem already stored is a warning. Runtimes and profiles are written together in one guarded transaction, and a conflicting change to either returns 409.

## 🚀 Features
* **Chat retention (experimental)** (#4385): A Hub-wide, age-based retention policy behind `hub.chat_retention`. It adds a hub-admin `chat_retention` settings section with `messages_retention_days`, plus a paced sweeper that deletes old messages along with their attachments, mentions and stars on SQLite and Postgres. Each run records per-project counts but no message content. History shows where retained history starts, and replies to removed messages show "[no longer available]".
* **Hub-signed workspace bootstrap downloads** (#4394): A Runtime Broker without Google Cloud credentials can bootstrap a hub-managed workspace. A GCS Hub gives it short-lived, GET-only signed URLs, one per file. Files download into a staging directory first, so a failed download leaves no partial files. Roll out the Hub first.
* **Held edits re-checked when they take effect (experimental)** (#4409): With `hub.agent_edit_held` on, held edits on a running agent stay pending until a start applies them. Before applying each one, the Hub re-checks that the principal who saved it may still edit the agent. Edits from savers who lost that permission are discarded and audited, and a re-check that can't be decided is refused with 503.
* **Cleared resource sub-fields apply at the next start** (#4411): Clearing one stored resources sub-field through config PATCH now takes effect at the next start on Runtime Brokers with the `clearedResourceSubfields` capability, instead of waiting for reincarnation. Roll the Hub out first, then the Runtime Brokers.
* **Artifact review editor improvements** (#4413, #4406): In the graphical review view, clicking one of your own comment badges edits it, and saving an empty note removes the comment. Links open in a new tab on Cmd/Ctrl-click or middle click. The artifact page gains a Refresh button that reloads in place without changing the base version of an edit, review or upload in progress.
* **Port view page links on the port-forward tunnel** (#4388, #4403): With `hub.port_view` on, page links are now served over the port-forward tunnel as well as conduit, and page view metrics are recorded. `scion expose` now explains what a page opened in a browser can load, and the port forwarding guide and the `scion-web-serving` skill cover both cases.

## 🔒 Security
* **Port proxy strips Hub identity headers** (#4388): The port proxy drops the Hub's internal authentication and identity headers before it forwards a request to an agent's exposed port, on both conduit and the port-forward tunnel.
* **More host git commands go through the host git door** (#4414, #4398): The shared workspace pull and clone fallback, worktree and branch lookups now run through the host git door. They get the same repository config policy check and before/after config check as other host-side git commands.
* **Declarative harness files stay inside the Agent home** (#4395): The declarative generic harness reads and writes its instructions and system prompt files through an Agent home handle. Paths outside the home and symbolic links in directory components are refused, and a link at the file is replaced rather than written through.
* **CSP report endpoint answers 204 and is rate limited** (#4393): Browser policy reports always get 204, including when they are refused. Each client is capped at 20 requests per second (burst 200), and only the first 100 reports in a request are read. Refusals are summarized in the logs.

## 🐛 Fixes
* **Token-created agents get delivery permissions again** (#4383): Agents created from a user access token now get `secret.deliver`, `env_var.deliver`, `skill_injection.deliver` and `secret.use` intrinsically, as session-created agents do. This restores the owner's shared user secrets for their descendant agents.
* **Runtime Broker control channel ordering** (#4399): The Hub always sends `connected` as the first frame of a control session, and PTY data, resize and close frames go only to the connection that opened the stream.
* **Telegram error replies are delivered** (#4410): Three group-chat error replies are now sent as plain text threaded to the sender's message. Before, Telegram rejected them because of an invalid parse mode.
* **Sign-in return path survives long URLs** (#4405): When the full return path doesn't fit in the session cookie, the path is stored without its query, so users still return to the right page.
* **Jump to agent palette closes when a pane dialog opens** (#4389): The terminal view no longer leaves two modals open at once.
