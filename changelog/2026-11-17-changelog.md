# Release Notes (2026-11-17)

This day renamed Choices to Decisions throughout, added experimental Workload Identity binding when minting GCP service accounts, and extended flat Cloud Run identity with host pairs and doctor checks. It also kept suspended agents from being knocked out of suspension by stale reports.

## ⚠️ BREAKING CHANGES
* **Choices are now Decisions on the wire and in the CLI (experimental)** (#4967, #4972, #4987): Under `web.decisions`, prompt and response messages are now `decision-prompt` and `decision-response`, and the set-answer route is `POST /api/v1/decision-prompts/{messageId}/answers`. Prompts sent before the upgrade (`choice-prompt` rows) no longer show as cards in chat history, and a set answer to one returns 404. Each decision in them can still be answered on its own with `POST /api/v1/decisions/{rowId}/answer`. `scion message --decisions` and `--decisions-file` are the new flags. `--choices` and `--choices-file` keep working as hidden, deprecated aliases, and the Hub still accepts the old `choices` request field for now.

## 🚀 Features
* **Workload Identity binding at GCP service account mint (experimental)** (#4975, #4985, #4992): Behind `hub.k8s_workload_identity_setup`, minting a project- or Hub-scoped GCP service account also grants the Kubernetes Workload Identity binding for the Runtime Brokers that use it. Runtime entries and flat runtime targets take a `workload_identity_pool` (`<project-id>.svc.id.goog`). The web mint dialog lists the bindings it made (a new one can take a few minutes to take effect), and the service account status view shows the binding as read from IAM.
* **Flat Cloud Run identity: host pair, passthrough grants and doctor checks** (#4974, #4982): A flat Cloud Run instance's `runtime_target.service_account` is recorded as the broker's GCP host service account and project, both on co-located activation and on `scion broker register --instance`. Passthrough identities get a provider-grant path. `scion doctor` checks Cloud Run API reachability and `iam.serviceAccounts.actAs` on every configured agent service account for flat Cloud Run instances, and the identity docs describe the setup.
* **GitHub triggers groundwork (experimental)** (#4970, #4984): Behind `hub.github_triggers`, the GitHub App settings take an `app_slug` and command mention aliases, the Hub reports trigger readiness and routes to a project's primary repository, and projects get a `trigger-sources/github` endpoint. The docs list the webhook and repository permissions the App needs.
* **Header mode switcher says Console** (#4983): The web UI header's mode switcher now offers Console, Chat and Terminal, so it no longer clashes with the Dashboard overview page.
* **Resume support shown with harness capabilities** (#4966): `scion list --format json` reports each agent's resolved harness type and its capabilities, including resume support, which is now decided the same way as the Hub's suspend check.

## 🐛 Fixes
* **Suspended agents stay suspended** (#4981): Once an agent is suspended, status and runtime reports from the agent or its broker no longer change its phase, activity or exit details. A late report can no longer clear the suspend reason or wipe the activity kept across suspend.
* **GitHub permissions view matches minted tokens** (#4973): For a project with no GitHub permissions set, `GET /api/v1/projects/{id}/github-permissions` now reports the same defaults that token minting uses, including `issues:write`.
* **Held web messages keep `@email` mentions** (#4980): A held web chat message that is delivered later now has its `@email` mentions translated again for the agent.
* **Messages tab scrolls on the agent page** (#4971): The agent detail Messages tab bounds its chat thread, so the thread scrolls and the composer stays visible. *(Contributor: Adis Bacic)*
* **Token usage on telemetry spans** (#4883): sciontool now adds `gen_ai.usage.*` token attributes (input, output, cached, cache write, reasoning) to spans whose start and end hooks ran in separate processes. *(Contributor: Professor X)*
* **hub-gke and release image tags** (#4999, #5000): The hub-gke image is stamped with its version. Release and nightly builds tag their bundled `scion-*` images with their own version instead of `latest`. The hub-gke Terraform configuration turns off the chart's GKE secret mode, so agent secrets go through namespaced Kubernetes Secrets instead of Secret Manager.
