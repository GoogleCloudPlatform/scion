# Release Notes (2026-11-03)

This period turned on asynchronous agent start by default, required template and harness-config names to be single path components, and made Cloud Run agents receive their full Agent home and Hub credential. It also hardened skill installs, repository cloning and GitHub App token minting, fixed a placeholder system prompt that was replacing harness prompts, and added more chat retention controls.

## ⚠️ BREAKING CHANGES
* **Asynchronous agent start on by default** (#4548): `hub.async_agent_start` is now on by default. Where the Runtime Broker supports it, `scion start` and resume are asynchronous and the CLI waits for the launch. Starts stay synchronous while any live Hub instance lacks support. When upgrading a multi-node Hub from a version without the Hub instance registry, keep the experiment off until every node is upgraded. Before a downgrade, turn it off and wait the launch timeout plus 15 seconds.
* **Template and harness-config names are single path components** (#4542, #4528): A template or harness-config name can't contain a separator or `..`, be absolute, start with `:` or contain `://`. The Hub and store refuse other names on every write. Agent create requests, scheduled `dispatch_agent` events and default templates must use a template name or ID. A project default template in another form is refused with an error naming the setting, and a default harness config in another form is dropped with a warning.
* **Per-agent workspaces on shared storage for Docker, Podman and Apple container** (#4533): On a shared (NFS) project storage layout, clone-per-agent and empty-per-agent workspaces are now placed on the share, as on Kubernetes. The container bind admits only the starting agent's own workspace. Agents provisioned before a storage switch are refused at start with a clear cause.

## 🚀 Features
* **Cloud Run agents get their Agent home and Hub credential** (#4545, #4537, #4518): At each start, the Runtime Broker copies the provisioned Agent home onto the instance's home on the shared volume, without following links and within size limits. Harness secrets and the agent's Hub credential travel with the staged secrets and go to an in-memory volume, never to the share. Start-up logs are quieter, and `scion doctor` checks the actAs prerequisite.
* **Chat retention preview and manual runs (experimental)** (#4526): Behind `hub.chat_retention`, Hub admins can preview what the retention settings, or a hypothetical window, would delete, and run a sweep manually. Admin > Server Config shows run history, the last preview and a backlog estimate, and asks for confirmation before enabling retention.
* **Token boundaries in the CLI** (#4538, #4522): `scion hub token list` shows a BOUNDARY column and filters with `--boundary project|hub`. `scion hub token scopes` takes `--boundary`, and `scion hub token create` sends an explicit boundary. Project lookups that find nothing under a user access token now name the `project:read` and `project:list` scopes they need.
* **Key verification and keyring without the legacy entry** (#4535, #4523): `scion server keys verify` checks that every stored secret authenticates under an allowed key and validates Hub backups, without changing anything. The encryption scan classifies values by the key that actually authenticates them. In keyring mode the Hub no longer needs a `legacy` signing entry.
* **Move-to-flat plan for legacy Runtime Brokers (experimental)** (#4515, #4547): `scion runtime-broker convert --plan` prints a read-only plan for moving a legacy, profile-based Runtime Broker host to flat instances, with environment values redacted. Behind `hub.flat_runtime_brokers`, legacy Runtime Brokers report the plan on each heartbeat and the Hub serves it through the API.
* **Warning when a start skips a secret** (#4534): When the secret store can't return a secret during start, resume or restart, the agent still starts, and the response now lists the skipped secret names in `warnings`. Values are never shown.
* **Artifacts remember the delegating user** (#4555): An artifact created by an agent records the agent's delegating user, so that user stays a steward after the agent is deleted.
* **Manage access dialog for artifacts (experimental)** (#4525): Behind `web.artifact_manage_access`, one dialog replaces the separate Share, Grant review access and Retention buttons on the artifact page.
* **Settings and doctor checks** (#4514, #4519): The Server Config page shows the running value of keys set at start-up, and `settings.yaml` mode validates the effective GCP identity pair. `scion doctor` checks that the configured shared-dir storage class exists and flags existing claims that use another class.

## 🔒 Security
* **Skills install without following links** (#4554): Template, platform and registry skills, and skills carried over on a harness-config switch, are copied into the Agent home through one writer. It skips symbolic links, special files and hard-linked files, never follows a link in the destination, and installs each skill as a unit within entry, size and depth limits.
* **Repositories clone only from `https`, `ssh` or `git` URLs** (#4531): Project repository clones during provisioning refuse other URL schemes.
* **Verified GitHub App token minting** (#4532): A token is minted from another project, named by the token-source label, only when the agent's own project has no installation and the source user may create agents in the named project. Every mint re-verifies the installation, and such a token is not treated as the agent's own project token.
* **Staged token marker and credential names** (#4552, #4512): Runtimes drop an inherited `SCION_HUB_TOKEN_STAGED` marker from the container environment, and token issue-time parsing is stricter. The Runtime Broker credential store validates names on load and delete as it already did on save.

## 🐛 Fixes
* **Placeholder system prompt no longer replaces the harness prompt** (#4549): The default template's `# Placeholder` system prompt was passed to Claude and Grok Build in place of their own prompts. Empty or placeholder-only content now counts as no system prompt.
* **Git config keys at agent start** (#4543, #4527): Agent start now carries `grep.threads`, `branch.<name>.vscode-merge-base`, `remote.<name>.promisor` and `remote.<name>.partialclonefilter` into the agent's copy of `.git/config`, with value checks. Keys that name a command or hook location are left out on Docker and Podman and named in the start notice. On raw layers and Apple container they refuse the start. A refusal now names every refused key, grouped by config file with its remedy, and is reported with the `git_config_refused` launch code.
* **Resume keeps delegation grants after a suspend** (#4520): A suspend now revokes only the grants of the suspended run, so a resume in the meantime keeps its own grants.
* **Reincarnate right after an async create** (#4357): A start claim is released as soon as a launch reports success, so a reincarnate right after an asynchronous create no longer gets 409 "a start is in progress".
* **Invalid shared-dir names on the local layout** (#4511): An invalid shared-dir name is skipped with a warning instead of failing the start. Valid names are still created and mounted.
* **Dark theme chat backgrounds** (#4510): The starred-only banner, reply preview and other chat elements now use defined theme tokens, so they are readable in the dark theme.
