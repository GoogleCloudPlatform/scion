# Release Notes (2026-11-12)

This day added an experimental way to switch an agent's harness in place, opt-in wake for scheduled messages, and web chat cards for multiple-choice decisions. It also cut Cloud Run cold-start checkout time and fixed several Runtime Broker and Hub startup edge cases.

## 🚀 Features
* **Switch an agent's harness with `reincarnate --harness` (experimental)** (#4784, #4788, #4787): Behind `hub.reincarnate_harness_switch` (alpha, off by default), a reincarnate request with a harness config moves the agent to that harness in place and has its Runtime Broker reset the agent's home. The Hub runs every check before anything is persisted or stopped, including a preflight for the target harness's credentials, and dry runs get the same checks. Brokers on Docker, Podman and Apple container runtimes support the home reset, as does Cloud Run. The old home is moved aside and purged in the background.
* **Choice cards in web chat (experimental)** (#4771): Behind `web.chat_choices`, a multiple-choice prompt from an agent shows as a card in web chat. A single-decision card records the answer on one click, or on Enter for the recommended choice. A multi-decision card (2 to 10 decisions) stages selections, counts what is still open and submits all answers at once. Cards show who answered, link a replaced decision to its newer version, and are disabled with a stated reason when you can't answer. The `choice-response` message shows as a compact line.
* **Opt-in wake for scheduled messages** (#4783): `scion schedule create` and `create-recurring` take `--wake`, which resumes a suspended target agent before the message is delivered. The API and both web schedule forms have the same option. The wake needs the `agent.lifecycle` permission and is refused, with nothing started, when it isn't held. Without the flag, a message to a suspended agent still fails, and chat scheduled sends never wake.
* **Multi-instance Runtime Broker conversion** (#4794, #4791): `scion runtime-broker convert --apply` and `--rollback` now handle a plan that converts a legacy host into several instances, and the co-located precheck resolves the Hub endpoint the way the server does.
* **Faster workspace checkout on NFS-backed runtimes** (#4781): `sciontool init` runs `git checkout` with parallel workers (default 16, set with `SCION_GIT_CHECKOUT_WORKERS`, 0 to 64). On a Filestore mount, a checkout of about 13.5k files measured 138 s with one worker and 31 s with 16, a large part of Cloud Run cold-start time.

## 🐛 Fixes
* **Flat agents keep ownership across project re-links** (#4792): When a shared-workspace project is re-linked to a new project ID, the Runtime Broker moves its ownership records along with it. Start-up reconstruction still attributes stopped runtime objects labelled with the earlier project ID, and finishes an interrupted move.
* **`container_hub_endpoint` applies to any Hub URL** (#4770): A broker's `server.broker.container_hub_endpoint` is now given to its Docker and Podman agents in place of the agent Hub endpoint even when that endpoint is a public `https://` URL, not only a loopback one. Brokers without it keep giving agents the public URL.
* **Terminal attach to a not-yet-connected agent is retried** (#4782): On the legacy Cloud Run runtime, an agent can show as running for minutes before it connects. A terminal opened in that window now gets a retryable 503 `agent_not_connected`, where it used to get a final `runtime_attach_unsupported` that the web never retried.
* **Reprovision keeps sciontool's `agent-info.json` keys** (#4786): Rewriting `agent-info.json` on reprovision now carries over keys that only sciontool writes (such as `toolName` and `activitySource`), and the write goes through a temp file and rename so a reader never sees a truncated file.
