# Release Notes (2026-11-20)

This day brought Hub branding to the web app, GitHub triggers that evaluate CEL rules, optional free-form "Other" answers on decisions, and opt-in Kubernetes service account creation with Workload Identity on flat brokers. It also tightened schedule targeting, agent token checks and config loading to fail closed.

## ⚠️ BREAKING CHANGES
* **The Hub won't start on an invalid `settings.yaml` server section** (#5076): A `server` section that fails to parse or decode now stops startup with the error. Before, it was silently ignored and the Hub ran on defaults.
* **Scheduled messages follow the strict message target rule** (#5188): Creating a message event or schedule now fails when the target agent doesn't exist yet, is deleted, has an `agentId` whose `agentName` doesn't match, or can't be read and messaged by the caller. That includes an unreadable cross-project target while cross-project messaging is off. Resuming a paused schedule, or a `PATCH` that changes its payload, cron, time zone or type, fails with 404 if the target no longer resolves. A scheduled message is sent under the authority of whoever last created, changed, resumed or re-enabled it, not the original creator.
* **A2A bridge `/metrics` requires authentication** (#5114): The bridge's `/metrics` endpoint now requires authentication, as the docs already said, is rate-limited, and returns 403 under the federation scheme. Metrics scrapers must authenticate.

## 🚀 Features
* **Hub branding** (#5088, #5158, #5170): Hub-wide branding settings now take effect. The Hub serves the branding assets and web manifest, branded pages use them, and the web app applies the brand colors. The CLI's local sign-in callback page is themed too.
* **GitHub triggers with CEL rules (experimental)** (#5108, #5150, #5155, #5168, #5183, #5187, #5179, #5145): Behind `hub.github_triggers`, triggers can be authored from the CLI or with presets, and webhooks are created in one call. Match rules written in CEL are evaluated in the dispatcher, and a trigger can dispatch an agent. Trigger activity is observable. Until rule evaluation landed, triggers with match rules failed closed instead of matching everything.
* **"Other" free-form answers on decisions (experimental)** (#5180, #5193): A decision can allow an "Other" answer with its own label and description, on single-decision and set cards. Users can also dismiss decisions straight from the chat card and the Decisions pages (#5167), and a decision response now wakes an agent the Hub suspended (#5141).
* **Kubernetes service accounts and Workload Identity on flat brokers** (#5175, #5182): With `runtimes.<entry>.create_service_accounts` (or `runtime_target.create_service_accounts` on a flat instance) set to `true` (default `false`), the broker creates the Kubernetes service account for a Hub-minted GCP service account. Flat Kubernetes instances accept Workload Identity targets.
* **Effective permissions viewer (experimental)** (#5144): Behind `hub.effective_permissions`, the admin Roles dialog has an Effective permissions tab, backed by `GET /api/v1/admin/effective-permissions`, showing what a user can do overall or in a project.
* **Orphaned NFS agent directories in the orphan report (experimental)** (#5127): Under `hub.runtime_orphan_reconcile`, the Hub also reports agent directories on shared NFS project storage that no agent owns.
* **GKE continuous delivery pipeline** (#5038, #5177): A Cloud Build pipeline under `deploy/cd/` builds images and deploys a Hub to GKE with Terraform. It includes a setup preflight and records each deploy's downgrade floor.
* **Smaller additions** (#5202, #5121, #5140): The agent page's Limits & Usage card shows inherited limits. `scion init` skips the local container-runtime check when it targets a remote Hub. An online broker reporting an unknown version is flagged as needing attention.

## 🔒 Security
* **Agent tokens need a recorded credential** (#5161): An agent token is refused with 401 `invalid_token` if it has no `jti` or its credential row is missing or revoked, including on token refresh and Conduit.
* **`gh` keeps a caller's `GH_TOKEN`** (#5132): sciontool's `gh` wrapper no longer replaces a `GH_TOKEN` the caller set. It replaces only the GitHub App token it injected itself.
* **Project member groups respect read access** (#5142): The project members view lists only groups attached to projects the caller can read.
* **Smaller hardening** (#5130, #5124, #5117, #5128): GCP telemetry export is turned off for agents in metadata `block` mode without credentials. GitHub API responses are read with explicit size limits instead of being silently truncated. An empty `PUT` to a project's GitHub permissions is rejected with 400 (use `DELETE` to reset), and stored empty sets count as unset.

## 🐛 Fixes
* **Messages and notifications** (#5058, #5211, #5115, #5213): An agent direct message whose outcome is unknown is marked failed instead of staying pending. The web UI backfills agent messages and notifications after an event-stream reconnect. Creators are now notified when a child agent is suspended. A chat thread's default agent stays current as you navigate.
* **Templates delete and sync take `--scope`** (#5024, #5216): `scion templates delete`, `sync` and `push` accept `--scope` (`project`, `global` or `user`), and a delete that would match templates in more than one scope is refused instead of guessing.
* **Agent create input checks** (#5137): `scion start` and `scion create` reject an invalid agent name, and a label with an empty value such as `issue=`.
* **Secrets kept across harness-config revisions** (#5086): An agent's declared secrets are restored when its harness config changes revision.
* **Smaller fixes** (#5162, #5181, #5148, #5152, #5126, #5099, #5209, #5015): Stopping all agents limits how many it stops at once. Losing project membership through a group change now goes through the same membership-loss handling as other removals. The GitHub App settings page has a corrected webhook hint and live health-check updates. Migration accepts a `.scion` marker file. A warning is logged when `harness_configs.<name>.args` is set for a harness that ignores it. Onboarding counts your own projects. A delete that fails on a directory owned by another user explains the UID mismatch. GitHub App handlers page through all projects.
