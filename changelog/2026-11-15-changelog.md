# Release Notes (2026-11-15)

This day brought experimental multiple-choice Decisions to profiles and the CLI with search, gave agents an `idle` status and harness-error reporting in place of false stalls, and laid groundwork for idle suspend, exec schedules and ephemeral Cloud Run agents. It also closed several authorization gaps around invited users, delegation standing and credential-less agents.

## ⚠️ BREAKING CHANGES
* **Helm releases named `*-scion-hub` are renamed on upgrade** (#4917): `scion-hub.fullname` no longer collapses a release name that ends in `-scion-hub` onto the same resource names as another release, so such releases get new names for namespaced and cluster-scoped resources on upgrade. That affects Workload Identity bindings, ServiceAccounts and RBAC. The install name `scion-hub` and names starting with `scion-hub-` are unchanged. To keep the old names, set `fullnameOverride`. Otherwise rebind Workload Identity after upgrading. The upgrade notes list the renamed cluster-scoped bindings.

## 🚀 Features
* **Decisions across projects, with search (experimental)** (#4908, #4896, #4918, #4879, #4893, #4894): With `web.project_decisions` on, the profile has a Decisions page and nav badge covering every project. The project Decisions page gains a filter panel, search and shareable URL state. Waiting decisions show as one pinned bell notification. In human mode, `scion decisions list` shows what is waiting on you, `--made` shows the answer log, and `--all-projects` rolls up every project. `-q` searches questions, answers, keys, agents and conversations, and `--conversation` and `--agent` filter. Agents can search their own decisions list too.
* **Agents report idle, and model errors no longer look like stalls** (#4884, #4888, #4874, #4919): `sciontool status idle "<reason>"` marks an agent idle without implying it is blocked or done. A harness that can't reach its model now shows a `harness_error` activity carrying the error, where it used to show STALLED with a stale "Ready" message. Long tool calls, builds and background jobs that emit no events no longer trip a false STALLED, because the Hub also checks the container for live work. Completed, idle and harness-error activities are kept across a suspend.
* **Suspend reasons and auto-wake (experimental)** (#4904): `scion list` and the API show why an agent was suspended (`user`, `idle` or `stalled`). With `lifecycle.idle_suspend` on, an agent the Hub suspended on its own is resumed automatically when a message, mention, notification or scheduled message arrives for it, with no `--wake` needed.
* **Invited-user guardrails in project membership** (#4891, #4902): An invited user who hasn't signed in yet gets their Hub role at first sign-in. Until then they can't be promoted with `scion admin promote`, added to a group that carries a built-in hub role, or have their status changed. The admin users page and project members editor show invited users and these limits.
* **Exec schedules and Conduit control routes (experimental, API only)** (#4906, #4895, #4875): With `hub.exec_schedules` and `hub.conduit` on, `POST /scheduled-events` accepts a one-shot `exec` event that runs a command in an agent through new Conduit exec routes. Each run is recorded, and a fire that can't run is recorded as `skipped`. Behind `hub.conduit_deliver`, message delivery over the agent's Conduit session has landed but isn't used yet.
* **Ephemeral agents on Cloud Run (experimental)** (#4877): Behind `hub.cloudrun_ephemeral_agents`, an agent can be created with `persistence: ephemeral`. The Hub refuses it while the gate is off, or on a broker that doesn't support it.
* **Release channel selector on the docs site** (#4921): The documentation site can switch between release channels and versions, and a banner points to a newer release in the same channel when one exists.
* **Plugin updates when the binary's directory is unwritable** (#4912, #4930): An admin plugin update whose binary was found on `$PATH` in a directory the Hub can't write, such as a root-owned `/usr/local/bin`, now installs the rebuilt binary to the plugins directory (`<pluginsDir>/broker/`), which is preferred on restart. If that isn't possible, for example because `settings.yaml` pins an unwritable path, the update fails with 422 and guidance, and the running plugin keeps running. It used to fail with a generic 500. The web UI shows the relocation and any warnings.

## 🔒 Security
* **Agents without credentials get none on start and restart** (#4901): An agent created without credentials (role `none`, the `none` auth choice, or the fallback when no credential was found) no longer receives secrets or harness credential settings when it is started or restarted, as was already the case at create. The only exception is the git token, `GITHUB_TOKEN`, taken from the project and then from the owner.
* **Identity-token minting checks delegation standing** (#4898): Minting an OIDC identity token is refused for an agent whose delegating user is suspended or removed from the project, even while the agent still holds an unexpired Hub token. This matches the other token endpoints.
* **sciontool strips credentials on cross-origin redirects** (#4886): When a request from sciontool to the Hub is redirected to another origin, credential and `X-Scion-*` headers are removed.
* **Capture-auth files follow harness-config policy** (#4910): Harnesses that don't use a container script no longer have `capture_auth.py` staged without checking the harness-config policy. When the script isn't there, the web terminal's Capture Auth action now shows a clear message (#4920).
* **Project reads write nothing for denied callers** (#4889): Reading a project now checks access before creating any missing project groups, so a denied caller triggers no writes.

## 🐛 Fixes
* **Reincarnate keeps gathered environment on every start** (#4900): Environment gathered during a reprovision is now carried into every start of a reincarnated agent, not only the first.
* **Heartbeats don't mix up agents with a reused name** (#4890): A broker heartbeat entry with the agent's name but another agent's ID is skipped for the current agent, so it doesn't mark the agent present or give it a status. The entry is left for the orphan report.
* **System image builds accept the bundled harnesses** (#4911): The harness list for system image builds now comes from the bundled harnesses instead of a hardcoded list that still included the retired `gemini` name.
* **@mentions with a possessive** (#4905): Mentions such as `@agent's` (with a straight or curly apostrophe) now resolve to the agent.
* **Notification subscriptions use the right project** (#4922): `scion notifications subscriptions` respects `--project` and no longer sends an unlinked checkout's local project ID.
