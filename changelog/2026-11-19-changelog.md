# Release Notes (2026-11-19)

This day made idle auto-suspend durable and visible in the web UI, gave scheduled agents their creator's identity and credentials, and let users dismiss stale decisions. It also added experimental message policies and GitHub webhook ingress, and made message delivery status honest when the agent isn't running.

## 🚀 Features
* **Idle status and auto-suspend in the web UI** (#5071, #5100): The web UI shows the `idle` and `harness error` activities and the reason a suspended agent was suspended, and admins can edit the idle auto-suspend settings. An idle suspend is now recorded durably. The Hub retries the final write, keeps its claim when the outcome is unknown, and the idle sweep recovers interrupted suspends. This addresses the crash and failed-stop recovery that the docs previously warned about.
* **Scheduled agents act as their creator** (#5103, #5089): An agent created by a `dispatch_agent` schedule or event is now owned by the schedule's recorded principal, with the same ancestry and default agent role an interactive create would give it. It also gets the environment variables and secrets that principal's create would gather from Hub storage, unless its role is `none`. This applies from each schedule's next fire.
* **Dismiss and see withdrawn decisions (experimental)** (#5084, #5082): Under `web.decisions`, users can dismiss decisions that are stale, with a reason, from the web or the Hub API. `scion decisions list --dismissed` and `show` display who dismissed them and why. Decisions an agent withdrew show as withdrawn in chat and on the Decisions pages.
* **Message policies (experimental)** (#5078): Behind `hub.message_policies`, project admins write CEL policies that govern what agents may send to users and conversations, with dry-run testing and a decision log. They're managed with `scion message-policy` and `/api/v1/projects/{id}/message-policies`. Agents can list and read active policies, and `project-viewer` (revision 2) can read them.
* **GitHub webhook triggers (experimental)** (#5079, #5080, #5095, #5097): Behind `hub.github_triggers`, the Hub accepts GitHub App webhooks, drops replayed deliveries and ignores events caused by its own App. Matching triggers dispatch work, and trigger events can be read through the API. Trigger rules can be written in CEL from the CLI.
* **Separate Conduit relays on GKE** (#5085): The Helm chart's `conduit.relayMode: external` runs Conduit session hosting in its own relay pods with PodDisruptionBudgets, apart from the Hub.
* **Hub branding settings** (#5088): The Hub gained a `branding` settings section as groundwork for Hub-wide branding.
* **Stall hint for agents that never reported** (#5059): An agent that stalls without reporting any harness hook event since start gets a status message saying so, which points at a startup problem.

## 🐛 Fixes
* **Honest delivery status and no stranded messages** (#5104): A message to an agent that isn't running is marked Agent unreachable instead of Accepted. Accepted now means the agent's runtime buffered the message, and Seen means the agent read it. An agent-to-agent message no longer stays pending when its sender disconnects or the Hub shuts down, and messages stuck as pending expire after 10 minutes.
* **Unknown runtime profiles are refused at create** (#5073): Creating an agent with a profile, active profile or profile runtime that the broker's settings can't resolve now fails before any work with `runtime_unavailable` and lists the valid profiles.
* **Failed starts roll back the run** (#5068): When a broker refuses a start with 503 `runtime_unavailable` before creating anything, the Hub reverts the agent's run ID and any reincarnate config change.
* **Cloud Run agents start in their workspace** (#5113): Agent containers on Cloud Run Instances now use the workspace as their working directory.
* **Generic harness command checks** (#5069): A built-in generic harness with an empty command is refused, and the runtime's shell wrapper is guarded.
* **Smaller fixes** (#5052, #5051, #5053, #5054, #5062, #5055): The Hub fails to open a file-backed SQLite database if WAL mode didn't take effect. Log attributes that Cloud Logging can't encode are replaced instead of breaking the entry. `scion hub brokers delete` shows the broker's projects. Discord tells an unresolved sender why an attachment-only message wasn't delivered. The A2A bridge handles `504 start_outcome_unknown` on agent create. Dark-mode colors are fixed in the web UI.
