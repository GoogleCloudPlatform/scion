# Release Notes (2026-10-05)

The end-of-turn assistant-reply mirror is retired, and chat can now wake a suspended agent when you send to it. Much of the day was spent hardening agent creation and deletion against races, on the Hub and on the Kubernetes runtime. Conduit now runs in the Hub behind its experiment flag, chat startup got much cheaper, and access-lifecycle rules were tightened.

## ⚠️ BREAKING CHANGES
* **Assistant-reply mirror retired** (#2582): sciontool no longer mirrors each turn's final text, and the Hub answers `assistant-reply` with 200 `{status: dropped}` before any side effect, so older agents stop flooding web DMs. Telegram Commentary (old buttons become no-ops), the `ShowAssistantReply` settings, the mirror rate class and the Google Chat relay are removed. Agents must reply on purpose with `scion message`. A2A uses explicit replies only. There is no DB migration, and upgrade order does not matter.
* **Agent start checks service account admissibility first** (#2542): An agent whose assigned GCP service account is unverified, deleted or otherwise inadmissible now gets a 400 at start, restart and CLI start/resume, saying what to fix, instead of failing later. Stop and suspend are unaffected. Failed verification saves now return 500 instead of being ignored.
* **Synchronous create answers 409 when the agent is deleted mid-create** (#2578): A synchronous create (full, `provisionOnly` or env-gather) whose agent is deleted while the Runtime Broker call is in flight returns 409 `delete_in_progress` instead of 201 with a warning. Async launches still answer 201.
* **Explicit `--project` / `-g` beats `SCION_PROJECT_ID`** (#2548): Inside agent containers an explicit project flag now overrides the env ID, including for `conversation`, `notifications` and `messages`. `-g global` in a Hub-connected context with no project ID resolves the Hub's Global project (slug `global`).

## 🚀 Features
* **Wake a suspended agent from chat** (#2555, #2554): A user allowed to start the agent gets a "Wake and send" dialog instead of "Agent unreachable". The agent resumes, the client waits up to 30 s for readiness, and the message is delivered as its first input. Retries are idempotent. Resuming on message wake now requires the agent lifecycle permission (403 otherwise), for user and agent senders alike.
* **Conduit runs in the Hub, experimental** (#2471, #2477, #2479, #2483, #2553): Behind the `hub.conduit` experiment, the Hub hosts the conduit relay at `GET /api/v1/conduit` with `server.hub.conduit` settings and startup checks. sciontool dials it with backoff, and the Hub port proxy uses conduit streams when available, falling back to the legacy tunnel. Sessions are admitted only for the agent's current run ID.
* **Shared NFS dirs work across Docker and Kubernetes agents** (#2575): Agents that mount NFS shared dirs get the leaf's group (pod `supplementalGroups`, or `--group-add` on Docker and rootful Podman), so agents on different runtimes can edit each other's files. Requires a new image. Rootless Podman and Apple warn and start unchanged.
* **Provisioned-but-not-started agents shown clearly** (#2507): `scion create` agents show "created (not started)" in the CLI list and every web status badge, with a start hint, instead of looking like a failed start.
* **Claude thinking levels** (#2525): `SCION_THINKING_LEVEL` 25/50/75/100 maps to `CLAUDE_CODE_EFFORT_LEVEL` low/medium/high/xhigh. A value already set in the container env wins.
* **Open agent DM from the quick message dialog** (#2541): A new button closes the dialog and opens the agent's DM, carrying over unsent text.
* **Faster chat and agent lists** (#2497, #2491, #2485, #2513, #2510, #2577): A cold `/chat` load drops from 19 to 6 API GETs. The space rail renders before thread lists load. The DM list drops from ~241 store queries to 5 for 80 DMs. Shell tray requests are sent once per page load. The agent graph loads the compact list view by scope instead of full agents, and the compact view now carries the detail message and deletion state.
* **Groundwork** (#2534, #2488, #2544, #2482, #2509, #2567): Inert or gated steps toward a persistent NFS agent home on Kubernetes (`hub.k8s_nfs_home`), pod recovery start claims, `reincarnate --broker` workspace placement, and the artifact system (`hub.artifacts`, default off).

## 🔒 Security
* **Tokens for deleted users rejected** (#2522): Hub JWT auth returns 401 `user_not_found` when the token's subject no longer exists, and `/auth/validate` reports `valid: false` for deleted or suspended users. Creating a nested group now applies the same parent-group checks, audit and member limits as adding a member.
* **Ownership and membership rules tightened** (#2514, #2540, #2495, #2501): The last-owner rule counts only usable owners (active user, binding in effect) and checks the state after the change in one transaction. Effective membership honours any active project binding, including custom roles. Project members groups can no longer be role-binding principals or child groups (400 `principal_ineligible`). A project slug rename only migrates groups that belong to that project.
* **Delegation edges follow agent delete, restore and reincarnate** (#2523, #2524, #2557): Agent create commits row, delegation edge, provenance and audit as one unit and rolls back after a failed dispatch. Restore reactivates edges (409 on conflicts), and reincarnate requires delegation authority in the target project. SA-assign denials for an unrecorded delegation edge now say how to fix it.
* **Passthrough on the embedded Runtime Broker** (#2545): On single-node deployments an unscoped local platform administrator may use passthrough on the co-located Runtime Broker. Other Runtime Brokers still require ownership.

## 🐛 Fixes
* **Agent creation and deletion races** (#2536, #2487, #2562, #2469, #2537): A creation or start that lands after its agent was deleted no longer revives it. Phase writes are skipped, and the started run is removed by run ID. `agent.created` is not published for a deleted agent. Previous runs are cleaned up when a start never lands, and a stale-run delete keeps a same-name successor's files. Restored agents show again in the web UI.
* **Kubernetes runtime** (#2515, #2551, #2481, #2480, #2538, #2494): Delete and run pre-clean are run-scoped and never remove another run's pod. NFS-home pods are deleted gracefully. Existing-agent operations use the runtime the agent's saved profile selects. Agents with no GCP identity are no longer refused at start (Hub upgrade needed). Content-hash template names stay off labels. Shared-plain git workspaces on NFS are now cloned instead of starting empty.
* **Agent lifecycle and Runtime Broker quota accounting** (#2508): A restart at `max_agents_per_broker` returns 429 without stopping the container. Every start path reserves the slot and writes `starting` before dispatch, restoring both on failure. Heartbeats no longer clobber the phase of an in-flight operation.
* **Configuration** (#2531): The settings schema matches the Go types, and schema env-var names reach the values the Hub reads. Unmatched `SCION_SERVER_*` names produce a startup warning. Top-level sections load without a `server:` key. Single-key settings writes edit `settings.yaml` in place, keeping comments.
* **Chat plugins work again after authorization changes** (#2572): Discord, Telegram, Teams and Slack plugins act as the linked user, restoring setup, agent lists, status and mention routing.
* **Web chat replies no longer vanish after Discord or Telegram use** (#2467): Wave-2 web sends record the `web` channel, so untagged agent replies show in Web/PWA chat again. *(Contributor: G. Hussain Chinoy)*
* **Hub API correctness** (#2496, #2489, #2484, #2475, #2573, #2533): Malformed list cursors return 400, not 500. Multi-node Hubs return the Runtime Broker's typed error from cross-node dispatch. Keys requests that never connected return 503 `keys_unavailable`. A Hub cancel removes a queued control-channel request. A project settings PUT that omits `activeProfile` keeps it. Per-profile attach capability refreshes on heartbeat.
* **`scion attach` in Hub mode** (#2561): Actionable close-code messages, clean terminal restore, fail-fast without a TTY, one shared flow for `attach`, `start -a` and `resume -a`, and Ctrl-P reaches the agent.
* **`harness-config sync` propagates deletions** (#2535): Files removed locally are dropped from the Hub record.
* **Chat UI** (#2568, #2547, #2564, #2560, #2556, #2543, #2517, #2532, #2473): Thread messages that reached no one show "Not delivered" (new `no_recipient` state). Thread and scroll position survive mode switches. Search jumps and stale loads after a conversation switch land correctly. Keys typed while a palette opens become its query. Trays drop responses for a previous user. Many iOS keyboard, narrow-phone and landscape layout fixes.
* **Web layout and dates** (#2559, #2558, #2528): Agent header badges wrap with the name. Project and Runtime Broker Created/Updated dates display. Long names stay inside their cards. *(Credit: miller79)*

## 🔧 CI & Infrastructure
* **Build & Test hang watchdog** (#2550, #2511): A 30-minute job timeout, plus a watchdog that dumps goroutines before killing a hung run. `pkg/store/entadapter` SQLite tests now run in a PR-gating job.
