# Release Notes (2026-10-06)

`scion reincarnate --broker` now really moves agents between Runtime Brokers, and reincarnate can patch an agent's settings on the way. Pod recovery start claims are switched on, Runtime Brokers can register headlessly with join tokens, and a Terraform path runs the Hub on GKE behind IAP. A broad authorization pass tightened user access token boundaries, relationship grants and path handling across the Hub and Runtime Brokers.

## ⚠️ BREAKING CHANGES
* **Harness-config upgrade order** (#2646): Upgrade the Hub first, or together with Runtime Brokers. Agents using file-based harness auth must re-authenticate (or be re-created) once after upgrade. Env secrets are unaffected.
* **Synchronous start answers 409 when it loses to a delete** (#2597): `start`, `restart`, and `POST /agents` on an existing agent (`scion start` / `scion resume` in Hub mode) now return 409 `delete_in_progress` with no agent body, instead of 200 or 404. The CLI prints the cleanup warnings from `details.warnings` (#2656).
* **Strict server-config PUT** (#2637): A PUT carrying any key the Hub would not persist (unknown or flat dotted keys) is rejected with 422 listing them, and nothing is applied. In DB mode a partial PUT keeps the lifecycle settings it omits, and concurrent lifecycle writes get 409.
* **Deleting a user who still owns agents is refused** (#2652): User delete returns 409 and lists every owned agent in `details.agents`, including agents started by those agents or the user's schedules. After the delete, the user's user-scope secrets and env vars are removed.
* **Project clone URLs cannot carry credentials** (#2591): Create, register and label updates refuse a clone URL containing a username, password, token, query or fragment. Move clone tokens to project secrets or the GitHub App.
* **Project slug and ID formats enforced** (#2607, #2592): Client-supplied slugs must equal their slugified form (400 `validation_error` otherwise). Project IDs read from `project-id` files and `.scion` markers must match the project ID format. Existing projects keep loading.
* **Group-send output and exit code** (#2682): `--format json` for group sends is now an object with `counts`, `results` and `retry_recipient` (the former array is `.results`). Partial delivery exits 3 instead of 1.
* **Kubernetes resource defaults** (#2596, #2640): Default requests for CPU (250m), memory (512Mi) and ephemeral storage (10Gi) are added only when neither a request nor a limit is set. Pods now get memory and storage requests they previously lacked. With `enforce_resource_defaults` false, pods without resources no longer get the old 2 CPU / 4Gi / 10Gi limits. A CPU request above 2 now raises the built-in limit instead of producing a pod Kubernetes rejects.
* **Auto-expose migration** (#2500): Run the new rerunnable maintenance migration `auto-expose-env-normalize` once per existing Hub to re-derive stamped `SCION_AUTO_EXPOSE_*` values.
* **Health summary drops `stall_config`** (#2706): `GET /api/v1/admin/health/summary` no longer returns stall settings. Edit them on the Server Config page.

## 🚀 Features
* **Cross-Runtime Broker agent moves** (#2623, #2674): `scion reincarnate --broker <target>` moves agents with empty-per-agent workspaces on a shared Kubernetes export with matching export identities, after a dry-run handshake. Quota moves to the target, a failed start rolls back to the source, and the source delete never touches the shared export. A new guide covers requirements, permissions and rollback.
* **Reincarnate with patched settings** (#2586, #2614, #2663): New `--service-account`, `--role`, `--model`, `--thinking-level`, `--harness-auth` and `--image` flags change the next generation. They require agent update permission, and `--dry-run` shows old → new. Reincarnate refuses up front on a disallowed GCP service account. Agents with empty-per-agent workspaces can now be rebuilt in place on local-disk runtimes (Docker, Podman, container).
* **Headless Runtime Broker registration** (#2702, #2713, #2643): `scion hub brokers join-token create <name>` mints a single-use join token (5m-24h TTL) that `scion runtime-broker join` redeems on a host with no Hub user credential. Workstation login saves the Hub endpoint, `scion runtime-broker status` waits briefly for a first heartbeat, non-default ports are remembered, and deregister keeps other settings (new `--purge-local`).
* **GKE Hub via Helm behind IAP** (#2689, #2529, #2527, #2651): New Terraform modules install the in-repo `scion-hub` chart behind a global load balancer with IAP. A non-root `hub-gke` image target and typed chart values (`adminEmails`, secrets backend, required image registry) come with it, and the Helm install page has been rewritten.
* **Pod recovery start claims on** (#2628, #2641): Every start runs under a claim. A held claim answers 409 `start_in_progress`. Queued stops on HTTP-only Runtime Brokers are applied from heartbeats, and stuck create rows are resolved.
* **Per-profile default GCP service account** (#2598, #2620): Projects can set a default service account per Runtime Broker profile (`defaultGCPIdentityServiceAccountIDByProfile`). The Hub warns about, and a new `gcp-sa-mappings` doctor check flags, project service accounts with no Kubernetes mapping.
* **Shared dir storage per dir** (#2580, #2617): `shared_dir_storage_backends` picks `local` or `nfs` per shared dir, with the nearest level winning. Agents granted NFS shared-dir groups get a group-writable umask (needs a new image).
* **Artifacts, experimental** (#2612): Behind `hub.artifacts` (default off): single-file publish and get (`scion artifact publish` / `get`), content-addressed storage, dedicated agent scopes and a web artifact page.
* **Hub health status** (#2504, #2709, #2691): `/healthz` reports healthy, degraded or unhealthy, and CLI tools treat degraded as up while naming the failing checks. Workspace reads are bounded at 2 s. Chat plugins no longer inflate the connected Runtime Broker count, and the health cards are readable in both themes.
* **Conduit** (#2666, #2638, #2650, #2683, #2574, #2668): An admin endpoint rotates conduit grant keys. Every loopback host form routes over conduit. The capability now travels in the dispatched experiment set. Aborted proxy responses are truncated, and proxied WebSockets get a close code on upstream loss.
* **Discord** (#2608, #2670, #2667): Answers given through question buttons reach the agent. Direct messages go to the user's Discord channel, and chat-bridge posters are listed as group participants.
* **Cloud Run secrets** (#2606): The Cloud Run and Cloud Run sandbox runtimes deliver resolved Hub, project and user secrets, with clear errors past their size limits.
* **Web** (#2726, #2680, #2653, #2492): Bulk "Reconnect all" and "Remove all inactive" actions on the terminal list. `waiting_for_input` shows as "Waiting for User". The shared agent store walks the compact view (-79% payload), and retained agent lists stay current through a 30 s delta probe.
* **Messaging** (#2700, #2693, #2583): Group sends and `broadcast --all` cap concurrency at 6. Unmentioned thread replies meant for an agent notify a human. A2A returns `input-required` for input-needed replies.

## 🔒 Security
* **User access token boundaries** (#2647, #2639, #2579, #2694): Every token is checked against its boundary at request time, and hub-only permissions are denied on project tokens. Session-only operations report a stable reason. Every Hub operation carries a recorded bearer disposition. Keys authorization uses the shared relationship evaluator.
* **Relationship grants need live project access** (#2601, #2657, #2505): Owner and ancestor grants for users, tokens and federated users require current, Hub-recorded project access. Legacy cross-project message rows are gated by participation.
* **Agent visibility** (#2662, #2593, #2633): Agent lists return only agents the caller can read. Deletion error, code and claim are shown only to unscoped platform administrators. An agent may read the status of an agent it directly launched.
* **Runtime Broker registration needs user credentials** (#2468): Registration, re-registration and secret rotation refuse agent, delivery, federation and on-behalf-of credentials. A Runtime Broker may rotate only its own secret.
* **Path containment** (#2584, #2571, #2570, #2626, #2610, #2526): Downloads and template caches write only inside their root. Resource file paths must be canonical. Worktree join paths are validated. Project delete removes only a direct child of one of the projects roots (local or storage backend), including the embedded Runtime Broker's local project dir. Owner IDs are range-checked.
* **Less detail in errors** (#2701, #2658, #2576): Workspace and async start failures send fixed text and log details on the Runtime Broker. Service account refusals give one message for both causes.
* **Group and membership cleanup** (#2635, #2609, #2622): Orphaned memberships are removed and not counted toward the last-owner check. Existing role bindings naming a project members group are removed at startup. Discord routes replies only from the plugin's own relay webhook.

## 🐛 Fixes
* **Agent lifecycle** (#2486, #2624, #2490, #2506, #2679, #2688, #2472, #2621): Restart aborts with a retryable 503 when its stop fails, instead of risking two instances. Synchronous launches are detached from the client request (Ctrl-C no longer rolls them back) and bounded at 120 s. Delete dispatches carry a `notAfter` fence, and Stop is run-scoped on Docker and Podman. An unresolvable saved profile returns 503 instead of falling back to the default runtime. Exec on a missing agent answers 409 `agent_not_running`.
* **Harness configs** (#2646, #2715, #2695, #2590): One shared resolver with provenance, and explicit profile image overrides rank first. Deleted built-in harness configs and templates stay deleted. Remote Runtime Brokers can download Hub-stored harness configs. Updates keep server-managed fields.
* **Hub-managed workspaces** (#2600, #2636, #2634, #2605, #2476): The Hub hands its upload bucket to the Runtime Broker, or returns 422 `workspace_storage_unconfigured`. Hub clones use the Hub project ID as their identity, and shared dirs resolve from the project record. Provision dirs and shared-dir storage are cleaned up on delete.
* **Session metrics and native usage reach the Hub** (#2703, #2673, #2681, #2642): Hook processes persist aggregator state between events, and native usage derivation activates after the harness env overlay loads. Cloud Monitoring no longer rejects batches with zero start times.
* **Colocated Docker agents behind IAP** (#2712): On single-node IAP deployments, Docker and Podman agents reach the Hub through a local endpoint.
* **Runtime Broker health** (#2516): A failed default runtime reports degraded, and `/readyz` returns 503.
* **Configuration** (#2671, #2521, #2632, #2498): Legacy settings writes keep v1-only keys. A bare `SCION_HUB` no longer breaks settings load. The Cloud Run editor saves `project_id` and `location` (re-enter values saved in file mode). An env-pinned GCP identity mode no longer clears the account on save.
* **Other Hub fixes** (#2546, #2512, #2502, #2594): Agent cloud logs no longer drop entries lacking a project label. A plugin failure on an outbound DM no longer causes duplicate retries. Decision audit writes are buffered with retry. Metrics dashboard days follow the viewer's time zone.
* **Harnesses and runtimes** (#2499, #2539, #2690): OpenCode config is written in the current schema. Owner IDs of 0 default to 1000. Cloud Run SSH exec quotes arguments.
* **CLI** (#2613, #2587, #2630, #2519, #2470): Template sync mirrors deletions, usage text appears only for argument errors, the default-branch probe never prompts, `hub secret list` honours `--format json`, and `scion keys` reports a created-only agent as not running.
* **Web** (#2687, #2627, #2603, #2581, #2530, #2615): Agents deleted on an earlier feed stay hidden, and agents restored while no feed was open show again. Detail page headers wrap long names. The quick palette shortcut followed by Enter no longer opens another conversation. Selecting a terminal focuses it. Navigation is consolidated, with skills page and a11y fixes.

## 🔧 CI & Infrastructure
* **Mergeability gate and Cloud Build** (#2599, #2685): The PR mergeability gate holds at most one pending run per PR. Cloud Build ignore patterns are anchored, so embedded files are uploaded.
