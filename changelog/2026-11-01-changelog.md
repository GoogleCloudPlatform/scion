# Release Notes (2026-11-01)

This day changed how settings errors are reported, locked NFS project storage mounts to each agent's allowed scope, and tightened several token authorization paths. It also added `scion hub settings`, `project-defaults` and `experiments` commands, per-schedule time zones, Cloud Run per-agent workspaces and resource limits, and Runtime Broker plugin updates alongside Hub updates.

## ⚠️ BREAKING CHANGES
* **One error envelope for the settings write APIs** (#4442): A rejected value now returns 422 `validation_error` with `details.errors`, each entry naming its field. A stale revision returns 409 `revision_conflict` with the expected and current revisions, and an unreadable body stays 400. Clients that match on 400 `validation_failed` should accept 422.
* **Saved `authorized_domains` now take effect** (#4424): On database-backed Hubs, a saved `server.auth.authorized_domains` is applied live and at startup. A node's `SCION_SERVER_AUTH_AUTHORIZEDDOMAINS` ranks first, then the saved list, then `settings.yaml`. Saves and resets that would block sign-in for the account making them are refused with 422.
* **NFS Hubs must see the project share** (#4458): On the `nfs` project storage backend, the Hub's `workspace_storage` readiness check now checks the share itself. A Hub with projects that can't see the share or its `subpath_root` answers 503 on `/readyz` and reports unhealthy on `/healthz`. A Hub that only holds state, with no share mounted, is not supported. The `project_storage_tree` key is retired for `nfs`.

## 🚀 Features
* **`scion hub settings`, `project-defaults` and `experiments` commands** (#4437, #4449): `scion hub settings get/set/unset/schema` manages the Hub server configuration, with compare-and-set on each section's revision and `--dry-run` that masks secrets. `scion hub project-defaults get/set/unset` and `scion hub experiments list/enable/disable/reset` cover project defaults and experiments.
* **Per-schedule time zones** (#4467): Recurring schedules can name an IANA time zone. The next run is computed in that zone, with documented daylight saving handling. API timestamps stay UTC, and an empty zone means UTC. The zone is available as a flag on recurring schedule creation and as a field in the web schedule form.
* **Cloud Run per-agent workspaces and resources** (#4453, #4433): On the `cloudrun` runtime, clone-per-agent agents now get their own NFS workspace instead of sharing the project checkout. Instances also get the agent's resolved CPU and memory, checked against Cloud Run's limits before anything is provisioned.
* **Runtime Broker plugins update with the Hub** (#4440): A Hub binary update also updates each installed Runtime Broker plugin (`~/.scion/plugins/broker`) from the same release, with the same checksum and pinning checks, and swaps it in atomically. A failed restart or boot-failure rollback restores the previous plugins.
* **Runtime Broker command path in health and doctor** (#4420): Runtime Broker health reports whether its control channel to each Hub works. The Hub health summary flags Runtime Brokers that are online but can't receive commands, and `scion doctor` and `scion runtime-broker status` show it too. `update-binary` and `rebuild-server` warn about required settings that are unset, such as `server.trusted_proxies`.
* **Explicit Unlimited for count limits** (#4419, #4457): On the project settings PUT, a default count limit of 0 means Unlimited, `null` clears it and a negative value is refused. The project settings page and the agent Edit page show Unlimited with Clear, and disable it with a reason when the Runtime Broker doesn't support it.
* **Server key status report (experimental)** (#4423): Behind `server.secret_rotation`, an admin-only `GET /api/v1/admin/keys/status` reports the Hub's keyring, signing and encryption rings, deadlines and readiness. `scion server keys status` and `scion server keys check` build the report and validate the keyring on the host. No key material is included.
* **Send receipts name the conversation** (#4462): Message send responses include `conversation_id`, and the CLI prints it with the message ID so the sender knows where to reply.
* **Delegated agent list (experimental)** (#4451): An agent delegated credential can list agents within its grant boundary, with a per-item read check, sealed cursors and one audit record.
* **Review toolbar stays in view** (#4422): In the graphical review view, the toolbar stays pinned while the document scrolls, and Comment is a 44px tap target on phones.

## 🔒 Security
* **NFS mounts limited to the agent's scope** (#4450, #4463, #4455): At agent start, Kubernetes, Cloud Run and Docker/Podman/Apple refuse any mount of the NFS export root, a parent directory or another agent's or project's tree. Only the agent's allowed set is mounted.
* **Tighter token authorization** (#4443, #4439, #4438): A user access token's user read needs `user.read` on the Hub user record. An access-constraint preview token is accepted only for its own constraint. A constraint window change needs relaxation authority.
* **Key and secret handling** (#4470, #4465): Without a keyring file, agent and user JWTs are accepted only with an absent or `legacy` key ID. In managed ring mode, GitHub App and chat secrets stored with no secret backend are sealed. Separate relays now hear grant key changes, so revoked keys stop working without waiting about 5 minutes for the next refresh.
* **Runtime Broker list hides `LocalPath` from non-readers** (#4454): `GET /runtime-brokers?projectId=X` includes each provider's local path only for callers who may read that project's provider records.
* **Harness provision manifest path check** (#4429): `sciontool harness provision` now requires a separator boundary, so a sibling directory with a shared prefix no longer passes.

## 🐛 Fixes
* **Stopped and suspended agents don't count toward the project limit** (#4441): Stop and suspend free the slot in `max_agents_per_project`. Resume, wake, restart and reincarnate at a full limit are refused with a specific message, and the admin quotas page shows the enforced count.
* **Remote start for local projects without git** (#4459): `scion start` against a remote Runtime Broker no longer fails with 400 for a local project without git, because the files for its Hub-managed workspace are now collected from the workspace root. If the upload fails, the agent created by that start is removed instead of being left provisioning.
* **Runtime Broker startup** (#4471, #4417): The Runtime Broker connects to the Hub before it checks the runtimes of non-active profiles. Those checks run in the background and report an unreachable runtime as a warning. A stored profile whose runtime is missing fails with a clear, retryable 503 naming the profile.
* **Placement refusals keep their cause** (#4434, #4456): Every agent delete path, and forced user deletion records, report the placement refusal's own 409 code. Offline Runtime Brokers no longer hide it, and a failed create's cleanup no longer removes the row.
* **Re-register keeps Runtime Broker profiles** (#4445): A re-register through the deprecated embedded form that sends no profiles or capabilities no longer wipes the stored ones.
* **Longer Hub-to-Runtime Broker request limit** (#4426): The limit is now a fixed 180s, up from 120s. The CLI create timeout rises to 4 minutes and the Runtime Broker write timeout to 210s.
* **Failed-message purge no longer stalls the Hub** (#4427): The hourly purge deletes in chunks of up to 500 rows using a new index, instead of holding the SQLite connection for about 10s.
* **Agent-to-user DM IDs match the stored message** (#4444): The `message_id` and timestamp in the send response now name the message that was actually stored.
* **Conduit ingress spreads bursts** (#4452): Pending placements are counted, so a burst of dials is spread across relays instead of going to one.
* **Settings and project identity edge cases** (#4446, #4431): Unversioned `settings.yaml` files using v1 placement keys are detected as v1, and Hub startup moves a cloned project identity's config only when it belongs to the same project.
