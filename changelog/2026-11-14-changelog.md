# Release Notes (2026-11-14)

This day finished splitting global catalog writes into their own permissions and retired the `core` skill scope. It also gave multiple-choice decisions a project-wide Decisions page, and fixed a batch of scheduler, harness-switch and runtime issues.

## ⚠️ BREAKING CHANGES
* **Global template writes need new permissions** (#4804, #4856): Creating, updating or deleting a template in the global catalog now requires `template.create_global`, `template.update_global` or `template.delete_global`. This matches the skill change of 2026-11-13. The `global-catalog-author` (revision 3), `hub-admin` and `super-admin` (revision 12) roles carry them. A custom role holding plain `skill.update`, `skill.delete` or `template.*` permissions no longer writes global records, so add the matching `*_global` permissions if its holders should. Web controls and CLI flows now follow the new permissions.
* **The `core` skill scope is retired** (#4852): Skills have three scopes: `global`, `project` and `user`. On startup, a one-time migration moves each `core` skill to `global`. A slug that collides with an existing global skill is renamed `<slug>-core` and logged. Stored `skill://core/<slug>` references in injected-skill settings are rewritten to `skill://scion/global/<slug>`. `scion skills create --scope core` is no longer accepted.

## 🚀 Features
* **Project Decisions page (experimental)** (#4829, #4849): With both `web.project_decisions` and `web.chat_choices` on, a project gets a Decisions page with three lists: Waiting on you, Waiting on others, and a Made audit log. The project header shows a live badge. The page is backed by `GET /api/v1/projects/{id}/decisions` (`tab=pending|made`). Decisions stay answerable after chat retention purges the original prompt message.
* **Recommended choices highlighted, not preselected** (#4851, #4831): On multi-decision cards, recommended choices are now outlined but not selected, so every decision needs a click. **Preselect recommended choices** in the profile's Choices card restores the old behavior. Choice taps and hovers on mobile no longer open the message menu or blank the chosen row.
* **Experiment-gated platform skills** (#4846, #4864): A platform skill, or part of one, can declare `experiment: <id>` in its frontmatter and is included only when that experiment is on. A Choices guide and a new `scion-artifacts` skill (gated on `hub.artifacts`) use this.
* **Separate internal Hub URL for broker plugins** (#4861): `server.hub.internal_url` sets the Hub URL that hub-managed broker plugins (Slack, Discord, Telegram, Teams) call the API on. Use it when `public_url` goes through a proxy the plugins can't pass. Plugins now also receive `public_url` for browser links.
* **Shallow-clone guidance for per-agent clones** (#4833, #4838, #4853): Per-agent clone containers receive `SCION_GIT_DEPTH` (`1` by default, `0` for full) and are told at startup how to deepen. Set `clone_depth` on a template or profile for more history from the start. A worktree-per-agent agent that falls back to an in-container clone, on Docker, Podman, Apple container, substrate or cloudrun-sandbox, is now labeled `clone-per-agent`, so it isn't promised worktree semantics.
* **Runtime orphan report (experimental)** (#4868): Behind `hub.runtime_orphan_reconcile`, the Hub records runtime objects that brokers report with no matching Hub agent. The report is read-only and deletes nothing.
* **Faster provisioning checkouts** (#4850): Shared clones and `git worktree add` now use the same parallel checkout workers as `sciontool init` (default 16, `SCION_GIT_CHECKOUT_WORKERS`).
* **Error-phase log line** (#4859): The Hub logs each agent's entry into the error phase with its stage and a sanitized message, so operators who only read logs can see why an agent failed.

## 🐛 Fixes
* **Codex agents no longer report completed after every turn** (#4832): The Codex harness stopped marking the task completed at each turn end.
* **Harness switch fixes** (#4845, #4836): A `reincarnate --harness` switch now carries the target harness's gathered `as_needed` environment into its start. Before, a codex to claude switch failed in the pre-start hook. A switch that fails after the Agent home reset names a recovery command the agent accepts.
* **Scheduled agents pick a broker like a manual create** (#4847): A `dispatch_agent` fire selects its Runtime Broker the way a manual create without `--broker` does, starting from the project default. Where a manual create would ask for `--broker`, the fire fails instead.
* **Containers left in a previous runtime are stopped** (#4858): On start and on an unscoped stop, the Runtime Broker stops an agent's container left behind in another runtime, for example after its profile's runtime or namespace changed, or refuses the start, so an agent never runs in two runtimes at once.
* **Restarting runtimes stop on `limits_exceeded`** (#4866): On Cloud Run Instances, which can restart an exited container, an agent that reports `limits_exceeded` now has its run stopped instead of being restarted.
* **Readonly agents can report their own status** (#4862): The `readonly` role gains `agent:status:update` for the agent itself. Agents that were already running get it on their next start.
* **Auto-suspend with custom harness configs** (#4863): Auto-suspend decides resume support from the harness type, not the config name, so agents on a custom-named config are no longer skipped without a log line.
* **Smaller CLI and Hub fixes** (#4834, #4857, #4837, #4855): `scion message --in/--at @agent` resolves the agent and rejects invalid targets. `scion look` fails when its capture exits non-zero, and keeps the error text off stdout. Schedule views say they show only the caller's schedules, and hint at a hidden name on a 409 or 404. A GitHub App repository removal matches the repository name case-insensitively.
